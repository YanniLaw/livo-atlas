# 固定训练预算的采样对照

此工具回答采样策略本身的影响。此前[完整在线对照](spatial-heldout-comparison.md)中的训练调用次数
受异步合并影响；本轮从空模型开始，让每个 train 观测按 ID 恰好训练一次、每次 20 步。
保留窗口为 10，每观测最多 1000 个高斯，沿用实际 OnlineGaussianModel 与 YAML 中的 Adam 设置。

## 输入与控制变量

使用上一轮 `uniform-1` 的已封口快照作为共同参考。冻结清单覆盖 172 帧，其中 150 train、
22 heldout，21 个预选查询。所有训练、RGB/深度监督和 coverage 预渲染都只能使用 train 观测。
每次运行应恰好 150 次训练、3000 个优化步；两策略每步使用的观测 ID 与最终高斯数量一致。
保留数据使用独立、经摘要核对的原始相机外参，再组合共同最终 SLAM 位姿。

空间邻居由同一参考快照通过在线共用的原生 C++ 逻辑在训练前选定。
这里比较固定选块下的模型质量，不评价策略改变地图后选块器会如何响应。
最终位姿并非轨迹真值；深度为稀疏 LiDAR 相机 z 一致性，不能直接当作稠密表面精度。
留出约束针对高斯训练；SLAM 前端仍使用完整传感器流，不能称为端到端未见这些观测。

## 跨电脑运行

先准备实际 CUDA/gsplat 环境以及原生 `livo_atlas_prepare_3dgs_views` 和
`livo_atlas_select_gaussian_neighbor`。从 `config/gaussian.yaml` 复制实验参数文件，设置
`gaussian.joint_render_policy: spatial`、`evaluation.max_output_mib: 1024`、
`evaluation.min_free_disk_mib: 1024`；如果指定 split_file，必须与快照归档清单一致。
worker 的设备、显存份额、学习率与深度权重均从该 YAML 读取。

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python tools/3dgs_probe/evaluate_gaussian_sampling.py \
  --map-directory /data/reference/gaussian \
  --keyframes /data/reference/slam/keyframes \
  --prepare-executable /sdk/bin/livo_atlas_prepare_3dgs_views \
  --selector-executable /sdk/bin/livo_atlas_select_gaussian_neighbor \
  --config /data/experiment.yaml --seed-policy uniform --random-seed 0 \
  --output /data/uniform-0
```

保持其余参数完全相同，分别运行 `coverage` / `uniform`、随机种子 0 / 1。
所有 GPU 任务顺序执行。采样位置不能强行设为相同，因为位置选择正是研究变量；
随机种子相同也不保证 CUDA 浮点归约逐位一致。
输出必须为新目录，工具按块清理准备数据，不复制 bag，不保存另一套训练模型。
运行失败或中断只留下 failure.json，不发布成功的 report.json。

```bash
python tools/3dgs_probe/compare_gaussian_sampling.py \
  --baseline /data/uniform-0 --candidate /data/coverage-0 --output /data/comparison-0
```

对比器核对划分、参考、最终位姿摘要、配置、选块计划、完整训练调度和高斯数量；
验证浮点样本 SHA、dtype/shape 与冻结观测摘要，逐条重新计算固定指标。
保留旧版 `evaluate_gaussian_submaps.py` / `compare_gaussian_holdout.py` 的历史划分与用法。

## 如何读结果与误差图

单块和联合结果分别汇总；PSNR 按总体 RGB MSE 推导，SSIM 按有效窗口加权。
共同深度只在同一查询中两策略都满足 alpha ≥ .05 的同一参考像素计算。
没有共同覆盖时返回空值与原因，不能把各自覆盖掩码上的误差直接作为配对比较。
coverage_transition 同时报新增覆盖、丢失覆盖与共同空洞。

最差六个查询各输出一张图，两行为 uniform / coverage。列依次为：参考、单块、联合
（没有邻居时仍是单块）、平均通道绝对颜色误差、覆盖空洞、稀疏深度绝对误差、联合颜色收益。
颜色误差红色固定范围 0..0.5；空洞为品红；深度误差红色固定范围 0..1 m，
无深度标签为深灰，标签处无渲染覆盖为品红；联合收益绿色为改善、红色为退步，固定范围 ±0.2。
图为缩略诊断，精确像素与浮点指标保留在 samples.npz 和 JSON 中。

交接视角的空洞或误差只能提示子地图一致性问题；单凭这些图不能认定是接缝、位姿漂移或遮挡的哪一种。
两次同场景重复只用于描述本地结果，不证明跨场景泛化或统计显著性。

## 本机完整结果（2026-11-26）

四次都完成 150 次训练、3000 步、21 个查询，包含 19 个联合查询。
共 13 个子地图，最终合计 120000 个高斯；每块至多 10000，末块只有 3000。
划分、原始资产、最终位姿摘要、配置、选块计划、完整训练顺序和数量均一致。
预选查询与上一轮参考最终评分的空间选块逐条一致，未选中的 heldout 17 也从未参与训练。
全部 float 指标重算一致，所有 PNG/NPZ 产物摘要和 518 个原始资产摘要逐项核对。

下表联合指标均使用相同的 19 个查询；深度另取四次共同覆盖的 **230532 个像素**，
占这些查询 254967 个 LiDAR 标签的 90.4164%。不能将各自掩码上的深度误差混入这张表。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| uniform-0 | 11.3090 | 0.287641 | 89.0015% | 0.233391 | 0.953786 | 20.407 |

两次描述性均值：coverage 联合 PSNR 增加约 0.899 dB、覆盖增加 4.26 个百分点，
SSIM 基本持平并略低。共同深度 L1 增加约 4.63 mm，RMSE 降低约 50.61 mm。
两次配对的共同像素集还分别保存（231561 / 231565 个），与四次交集不能混用。
因此可判断覆盖/RGB 收益在固定训练预算下仍存在，但结构与深度收益并不全面。

单块结果使用全部 21 个查询：uniform 两次 SSIM 为 0.235950 / 0.235945，
coverage 为 0.222219 / 0.221430；PSNR 从约 9.506 升至 9.788 dB，覆盖从约 79.94% 升至 83.46%。
每次仅 5/21 个单块查询的 SSIM 改善；联合 RGB MSE 每次 17/19 个改善。
联合相对各自单块在全部 19 个查询中都降低 RGB MSE，但这不证明接缝不存在。

### 空洞与交接视角诊断

两组最差六个视角均为 1、137、9、169、73、97（按误差降序）。查看生成的统一量程图后：

- 137 的建筑立面和 9 的画面右侧仍呈明显的点状覆盖与大片缺失。coverage 扩大支持区域，
  但并未恢复完整纹理；该现象与较低的单块 SSIM 一致，不能仅凭 PSNR 判定细节改善。
- 联合覆盖的新增像素为 374151 / 374557，同时丢失 111219 / 112857 个原有覆盖像素。
  单块新增 593530 / 592941，同时丢失 354379 / 353469；存在明显的定额分配取舍。
- 查询 1 早于所属块最终保留窗口的起点 6，且第一块没有历史邻居；coverage 的 PSNR
  从 6.420 降至 6.210。窗口淘汰值得后续单独研究，但其余最差五个查询并不早于各自窗口，
  所以不能把当前画质问题全部归因于 FIFO。
- 查询 169 所属末块只有 3 个训练观测，不能将该冷启动视角当成满容量稳定状态。
  现有图没有提供足以证明或排除跨块几何接缝的证据；它们是交接视角诊断，不是接缝真值。

### 资源与范围

本机为 x86_64、RTX 4060 Laptop 8188 MiB、驱动 535.183.01。
GPU 任务顺序运行，OMP/BLAS 为 1。训练平均调用耗时 uniform 为 136.0 / 150.6 ms，
coverage 为 160.5 / 164.2 ms；训练总时间均值增加约 13.24%。这个均值包含模型初始化及配置检查，
不是在线训练 P95，也不是实时前端延迟。完整离线过程约 48.34 / 50.68 / 52.37 / 52.36 s
（uniform 两次、coverage 两次）。
各块训练阶段 CUDA allocator peak allocated 约 96.5 MiB、reserved 112 MiB；
这些是 PyTorch 分配器统计，不是全进程显存，也不包括桌面显示服务。
四套评分产物约 1.6 GiB；不复制 bag 或保存另一套模型。
离线训练使用最终位姿，从空模型按固定序列训练，不能把绝对画质与上一轮历史在线训练直接相减归因。

## 下一项优化建议

保持默认 uniform。优先将现有固定的 **50% 空洞种子预留比例**改为 YAML 参数，
在相同窗口、高斯总数和训练步数下比较 0% / 25% / 50%，研究覆盖与纹理的取舍。
这比同时增加高斯数量、增密、改窗口或调深度权重更容易判断原因。
验收同时观察新增/丢失覆盖、单块与联合 SSIM、共同深度 L1/RMSE 和训练耗时。
本轮先完成诊断，不实现该算法调整；现有留出视角已经用于开发选择，后续独立结论仍需新场景或未参与选择的测试集。
