## P1：核心架构重构

### P1-A 公共契约

- [ ] 定义 ID、时间、位姿约定与标定对象。
- [ ] 定义传感器输入、同步事件、FrontendOutput、质量状态。
- [ ] 区分 LIO 中间输出、LIVO 完成输出和初始化/降级结果。
- [ ] 编写旧 ROS 消息、配置数组与新类型之间的适配函数。
- [ ] 明确图像与点云是否拷贝、谁拥有存储以及发布后的不可变要求。

涉及文件：`common_lib.h`、`LIVMapper.h`；新增 `core` 类型。旧滤波数学类型可以暂时保留，避免首批改动扩散。

验收：新契约可表达现有模式；所有状态和点云都有明确参考时间与坐标。

### P1-B 提取外围职责

- [ ] 将参数加载提取为 ROS 配置适配器；核心接收配置对象。
- [ ] 将 odometry、path、TF、图像、点云发布提取到 RosPublisher。
- [ ] 将轨迹、PCD、图像保存提取到独立输出组件。
- [ ] 将输出目录改为运行参数，建立独立会话目录。
- [ ] 将使用当前系统时间的状态输出改为观测时间，单独记录此行为修正。
- [ ] 保留原启动配置兼容入口，逐一记录默认值。

涉及文件：`LIVMapper.cpp` 的参数、发布和保存函数，`vio.cpp` 的 COLMAP 输出调用。

验收：算法执行路径不直接操作 ROS 发布器和文件格式；原 launch 可继续启动。

### P1-C 同步与前端封装

- [ ] 逐段提取 SensorSynchronizer，保留扫描切分及点时间语义。
- [ ] 将 IMU 消息转换放到适配边界，保留积分顺序和数值类型。
- [ ] 引入 FusionFrontend，统一拥有 IMU/LIO/VIO 与滤波状态。
- [ ] 把 handleLIO/handleVIO 迁入前端受控处理流程。
- [ ] 增加融合周期结束的唯一结果出口；处理 VIO 提前返回。
- [ ] 收紧公共成员，提供需要的只读诊断接口。
- [ ] 增加 SlamSystem 负责输入处理、结果分发和关闭。

涉及文件：`LIVMapper.*`、`IMU_Processing.*`、`vio.*`、`voxel_map.*`、`main.cpp`。

验收：更新顺序与基线一致；外部不能直接修改滤波状态；同步和前端可以由离线应用驱动。

### P1-D 所有权与构建清理

- [ ] 按所有权关系替换裸拥有指针，保留必要的明确非拥有引用。
- [ ] 定义重置、初始化失败和重复启动时的清理行为。
- [ ] 统一命名空间与格式配置，格式调整单独提交。
- [ ] 拆分 CMake target，逐步替换全局编译设置。
- [ ] 清理路径宏和非必要头文件依赖。
- [ ] 迁移目录并更新 include；单独检查 launch 和输出兼容性。

验收：P0 数据回放比较完成；长时间运行、正常关闭和失败路径有记录。没有数据验证的项目保持未勾选。

## 第一轮提交顺序

1. 设计文档与基线记录。
2. 公共契约和适配函数。
3. ROS 输出提取。
4. 文件输出和路径管理提取。
5. 同步器提取。
6. 前端封装与结果出口。
7. 生命周期、所有权清理与目录迁移。

每批避免同时修改滤波方程和工程结构。算法修正应有独立动机、对照结果及提交说明。
