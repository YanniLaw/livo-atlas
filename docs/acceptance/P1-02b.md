## 实现记录

- `include/livo_atlas/core/camera_config.h`：以 `std::variant` 保存五种模型各自的参数；无 ROS 依赖，验证尺寸、焦距/主点、畸变系数和适用模型的 scale。缩放仅对 Pinhole、Equidistant 生效。
- `include/livo_atlas/ros/camera_config.h`、`src/ros/camera_config.cpp`：按旧参数名读取并验证，缺少必需项或类型错误时报告完整参数名；仅沿用 Vikit 确有默认值的项。保留全部五个 Vikit 构造分支，并检查 Ocam 标定文件可打开。
- `src/main.cpp`：与传感器外参一起、在构造 `LIVMapper` 前加载相机配置；配置错误返回1。
- `include/LIVMapper.h`、`src/LIVMapper.cpp`、`include/vio.h`、`src/vio.cpp`：mapper 接收值配置；VIOManager 以 `std::unique_ptr` 持有 Vikit 相机。图像 resize factor 显式来自配置，Ocam、Polynomial、ATAN 固定为1.0，避免读取 Ocam 未初始化的 Vikit scale 字段。
- `CMakeLists.txt`：仅对相机工厂编译单元设置与 Vikit 相同的 Eigen ABI 架构选项；其他映射代码仍按系统 PCL 兼容选项编译。
- `tests/camera_config_test.cc`、`tests/data/ocam_camera_test_calibration.txt`、`CMakeLists.txt`：增加核心校验与五种模型工厂/缩放语义测试。
- `tools/check_camera_startup.py`：增加隔离 ROS master 的启动失败检查，覆盖未知模型、缺失必需内参、错误参数类型、零焦距、无效尺寸和非正 scale；沿用源日志备份与哈希检查。非有限值由核心单元测试覆盖。

### 验证中发现与处理

初次相机单测在销毁 Pinhole 相机时触发非法释放。检查发现 `vikit_common` 使用 `-march=native` 构建，而本项目为兼容系统 PCL 不对全局代码使用该选项；Eigen 对齐相机对象跨越了这两个编译边界。将匹配 Vikit 架构选项限定在 `src/ros/camera_config.cpp` 后，五种模型工厂测试及全部单测通过。其余代码仍保留原系统 PCL 兼容编译设置。

沙箱内启动 ROS 的首次尝试因本地 socket 权限被拒绝，没有运行到测试用例；使用本机权限重跑后，6项检查全部通过。bag 也先在沙箱内遇到相同 socket 限制，保留的失败尝试位于 `validation/P1-02b/short_a/`；本机权限下的完整结果位于 `short_b/`。这些是运行环境限制，不是 mapper 检查失败。

限制：Ocam 预检确认标定文件非空且可打开；Vikit 当前构造接口不返回标定内容解析状态，因此无法在构造前识别“可读但内容格式损坏”的文件。
