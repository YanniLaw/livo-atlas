# 保持 uniform 位置的定额补洞

原 coverage/resample 在预留空洞点后，会在剩余集合上重新均匀采样。
本轮增加 replace：只替换部分已覆盖的 uniform 位置，其他初始化位置保持不变。
alpha覆盖只是可移除位置的启发式，不证明纹理冗余，也不保证训练后的覆盖一定更好。

## 参数与规则

```yaml
gaussian:
  worker:
    seed_policy: coverage
    coverage_uncovered_ratio: 0.25
    coverage_sampling: replace
```

默认仍为 uniform、resample、比例0.5。以上只展示采样设置；在线 coverage 仍需要原有持久子地图配置。
coverage_sampling 仅接受 resample / replace。uniform 忽略该设置，coverage 的零比例跳过覆盖预渲染。

对有效深度像素 V，首先生成原来的 uniform 位置 U（N个）。在已有、且下次插入后仍保留的
高斯上预渲染当前训练相机，以alpha<.05定义空洞H。令 C=U\H、A=H\U，
替换数为 `q=min(floor(N*ratio), |C|, |A|)`。在C/A中分别按行序均匀选q个移除/加入位置。
最终保持N个互不重复的种子，保留N-q个原位置，U中原有空洞点全部保留。
没有历史模型、全部空洞、没有空洞、候选不足或比例0时保留uniform。

replace 的比例是最大**替换数**，resample 的比例是最大**优先预留数**；两者不是最终空洞种子占比，
也不能据相同比例认定实际改动点数相同。训练仍优化高斯均值；保留初始化像素不等于最终地图覆盖保留。

训练记录包含 uniform_uncovered 和 replaced_seeds；reserved_uncovered 在replace中固定0。
比较器验证上下界与q公式。实际位置保留通过CPU数组/随机掩码性质测试和CUDA冻结均值测试验证；
逐训练调用的保留数量由N-q推导，不将其当成训练后覆盖测量。

## 固定预算对照

沿用[固定预算入口](controlled-gaussian-sampling.md)，两种方式在同一比例下配对：

```bash
python tools/3dgs_probe/evaluate_gaussian_sampling.py \
  --map-directory /data/reference/gaussian --keyframes /data/reference/slam/keyframes \
  --prepare-executable /sdk/bin/livo_atlas_prepare_3dgs_views \
  --selector-executable /sdk/bin/livo_atlas_select_gaussian_neighbor \
  --config /data/replace-25.yaml --seed-policy coverage --random-seed 0 \
  --output /data/replace-25-0

python tools/3dgs_probe/compare_gaussian_sampling.py \
  --baseline /data/resample-25-0 --candidate /data/replace-25-0 \
  --allow-coverage-sampling-change --output /data/comparison-method-25-0
```

该开关只允许resample→replace，比例和其他YAML/WorkerOptions必须按类型精确相同。
与 --allow-coverage-ratio-change 互斥；默认比较和比例比较不会放行额外方式变化。
旧记录缺少新字段时仅补默认resample；真实replace配置不能因此降级为旧方式。
原配置字节摘要、完整归档、位姿、留出隔离、损失调度、产物与原子发布校验继续生效。

本机使用同一172帧参考、150train/22heldout/21query、19个联合查询，固定最终位姿与原生空间邻居。
五个条件各两次：coverage/resample/0（uniform等价控制），以及resample、replace各自25%/50%。
十次使用同一代码版本，GPU顺序执行，每次150次训练/3000步、窗口10、每观测上限1000、每块上限10000。
相同比例下比较方式，另对原resample相对0做比例比较。共同深度采用十次均覆盖的同一像素集合。
这个bag继续作为开发验证，SLAM前端使用完整传感器流；结果不用于直接修改默认或宣称泛化。

十次均成功，每次150次训练/3000步、21个查询/19个联合查询、最终120000个高斯。
原始资产、完整归档配置、位姿、选块、损失观测ID、种子数量和替换计数均核对通过。

## 位置保留与覆盖并不是同一指标

每次累计初始化150000个种子（包含之后随窗口淘汰的种子），最终地图另为120000个高斯。
replace25%两次各替换34151个、保留115849个uniform初始位置（约77.23%）。
replace50%替换65032/64917个、保留84968/85083个（约56.65%/56.72%）。
这些由实际训练调用的q按算法不变量推导，位置性质通过实际数组与CUDA单测验证；
没有记录每个调用的完整像素ID，也不把这些数量解释为最终优化后位置保留。

先用每次重复对应的0%结果作为**同一个uniform覆盖基准**。丢失数定义为
`image_mask & (uniform_alpha >= .05) & (target_alpha < .05)`，单块使用21个查询，联合使用19个。
相同比例的两种方式都对这个基准测量，而不是互相作为覆盖保留的基准：

| 比例/重复 | 单块丢失：resample → replace | 联合丢失：resample → replace |
| --- | ---: | ---: |
| 25% / 0 | 369301 → 149956 | 156927 → 39711 |
| 25% / 1 | 364688 → 147390 | 157421 → 39811 |
| 50% / 0 | 360380 → 267648 | 115334 → 57660 |
| 50% / 1 | 353951 → 264299 | 114549 → 54055 |

按两次丢失数相加计算，25%时replace减少约59.5%的单块损失、74.7%的联合损失；
50%时分别减少约25.5%和51.4%。这说明它明显改善了uniform原有覆盖的保留，但没有完全保持覆盖。
两次uniform基准覆盖像素数：单块5440099/5439993，联合5479608/5479557。
上述减少比例的分母是resample丢失数，不是全部基准覆盖数；逐查询计数和保留率记录在
audit.json的uniform_reference_coverage中。

另一个不同的问题是**replace相对resample本身**改变了哪些覆盖像素：
25%两次联合新增209697/209358、丢失156868/153064；50%新增165335/167422、丢失124379/120939。
这些是方式之间的周转量，不能用来否定上表相对uniform的保留改善。
初始化位置保持并不保证最终渲染覆盖完全保持，也没有恢复单块SSIM。
已查看25%配对的137视角统一量程图，立面支持区域有所变化，但点状空洞和缺失纹理仍明显。

该实验只能说明“仅保持初始化位置”不足以解决当前单块纹理损失；
它没有证明位置扰动完全无关，也没有确定损失的唯一原因。alpha覆盖不代表光度冗余，
且全部高斯仍会在后续训练中更新，这是下一步需要区分的两个因素。

## 资源、验证和本机证据

正式试验沿用4096MiB最小空闲显存、40%分配器预算、OMP/BLAS为1，GPU任务顺序执行。
少量CPU配置/兼容性校验与训练同机进行；未与其他GPU回归任务并行。

## 结论与后续

默认仍为uniform、coverage/resample/0.5。replace只作为显式可选实验方式，
它明显减少了uniform原有覆盖丢失，但未达到同时恢复单块SSIM的目标，
不推荐据本轮数据整体替换原方式。
25%下联合图像指标有小幅收益，同时存在单块与深度代价；50%的结构和深度代价更明显。

下一步先诊断被移除点的纹理梯度/多视图贡献，以及保留点在优化中的尺度、颜色和位移变化，
验证alpha覆盖能否用来判断冗余，再决定是否增加选择约束。保持同一预算单独做因果对照，
本轮不继续叠加新的采样规则、增密或后端变化。
