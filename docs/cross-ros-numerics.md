# ROS1 / ROS2 数值差异定位（2026-11-26）

已用单变量实验确认两处早期差异：PCL 的体素内排序，以及 Eigen 版本对 LIO 状态
更新的影响。输入转换、首帧预测状态和去畸变点云在本次采样中一致。
本轮保留生产算法、依赖和构建配置，实验代码位于工作区 validation 中。

背景为 [Humble 完整回放](humble-full-validation.md)：同环境两次重复一致；与 Noetic
对照的位置 RMS 差异为9.385 mm，关键帧169/172。目标是找出首次分歧，再决定如何处理。

## 从现有记录到高精度采样

首先比较已有记录：`imu.txt` 的27385行一致；最早可见差异位于第一次成功 LIO 更新后，
早于 VIO。原日志只有有限输出精度，因此另用诊断共享库截取首次 `BuildVoxelMap` 和
`EstimateState` 的输入、输出，以17位有效数字保存。

采样没有修改节点文件。两端带探针的 `mat_out.txt` 均逐项匹配原完整回放的对应前缀。
Noetic 的1秒采样因不足10行轨迹被旧验收器拒绝，改用2秒后正常通过；未降低验收条件。
Humble 的1秒采样正常通过。采样用于诊断，不用于性能比较。

首个成功 LIO 更新相对起点约0.300473秒：

| 边界 | 比较结果 |
| --- | --- |
| 生效体素参数和外参 | 一致 |
| 预测状态、传播状态，各386个标量（含协方差） | 一致 |
| 去畸变点云，20203点 | XYZ、intensity、curvature 五字段一致 |
| 体素滤波输出，10384点 | 1114点中的1853个标量不同 |
| 首次更新后的状态 | 最大标量差约 `5.06e-8` |

体素输出的 XYZ 单字段最大差为 `1.90735e-6 m`，intensity 一致；curvature 最大差为
`1.52588e-5`，不能将不同字段的混合最大值直接解释为位置误差。

## PCL 排序：单变量复现

本机 PCL 1.10 的 `filters/impl/voxel_grid.hpp` 使用 `std::sort` 按体素索引排序；
Humble 的 PCL 1.12.1 使用 `boost::sort::spreadsort::integer_sort`。二者都把同一体素的
点放在一起，但体素内的累加顺序可以不同。浮点加法对累加顺序敏感。

在同一 Humble 环境、同一 GCC 11、同一20203点输入上运行两个独立滤波程序：

1. 使用原始 PCL 1.12 头文件，输出逐字节匹配实际 Humble 采样。
2. 只在私有头文件中将排序替换为上述 `std::sort`，输出逐字节匹配实际 Noetic 采样。

系统 PCL 头文件没有改动。两个程序均显式实例化所选实现，未依赖动态库偶然选择模板。
此实验确认了首次体素输出差异的来源，不代表所有后续数值差异均来自排序。

## Eigen：隔离首次 LIO 求解

再用诊断共享库在 Humble 中替换该排序。滤波点、变换后的点、点协方差及采集的初始
平面几何/协方差字段全部恢复与 Noetic 一致；更新后的状态仍有约 `2.22e-16` 的标量差异。

将相同参数、状态和滤波点交给独立程序，直接编译生产 `src/mapping/voxel_map.cc`，
固定 GCC 11、PCL 1.12、OpenMP 预算和输入，只切换 Eigen 头文件：

| Eigen 版本 | 首帧 LIO 状态输出 |
| --- | --- |
| 3.4.0 | 逐字节匹配排序替换后的 Humble 采样 |
| 3.3.7 | 逐字节匹配 Noetic 采样 |

比较覆盖状态及协方差的全部386个标量。这确认了该次状态更新对 Eigen 版本的数值
敏感性。没有将旧 Eigen 混入正式节点，也没有据此宣称统一版本后整段轨迹必然一致。

## 完整回放控制实验

保持 Humble 节点和依赖不变，仅通过诊断共享库恢复上述排序，再完整回放官方 bag。
节点仍处理30157条输入，DDS 序列化载荷及输入计数检查通过，LIO/VIO 为1352/1351，
13次回环查询完成、接受2次、最终版本2；回环归档检查为 `consistent`。

与同一 Noetic 参考按1352行相同传感器时间比较，不做轨迹对齐：

| Humble 配置 | 位置 RMS差异 | 最大位置差异 | 最终位置差异 | 关键帧 |
| --- | ---: | ---: | ---: | ---: |
| 默认排序 | 9.385 mm | 49.896 mm | 1.048 mm | 169 |
| 实验排序替换 | 10.956 mm | 55.708 mm | 0.122 mm | 172 |

在同一 Humble 环境内，两种排序的轨迹彼此相差 RMS 4.604 mm、最大30.852 mm。
这说明排序影响会传播到完整输出，但替换排序没有消除跨环境差异，整体 RMS 也未降低。
实验共享库不作为正式修复或默认实现。

## 工程结论与边界

直接证据位于普通 C++ 前端：首先是体素滤波，其次是状态求解。两处均已做单变量复现；
尚未对整段轨迹的全部后续差异逐项归因。迭代更新、匹配及关键帧阈值对小扰动的放大
是可能机制，未在本轮进一步分解。

后续回归建议：

- 同环境固定源码、参数和数值依赖，检查确定性结果、输入完整性及最终归档。
- 跨环境记录依赖版本、轨迹差异、关键帧和回环结果，不承诺逐位相同。
- 本 bag 的差异仅为两个估计结果之间的对照，不作为真值精度或通用容差。
- 后续先收敛数值回归契约及依赖记录。若需要跨 PCL 版本稳定的体素行为，再单独设计
  项目控制的实现；这属于算法行为变更，需要重新建立基线。

原始 bag、3份转换数据文件、331个生产源码/配置/工具文件、节点和27个控制实验加载库
的校验通过。控制回放成功后精简344份载荷，共220677041字节；元数据、日志和清单保留。
容器已恢复停止，生产代码与构建配置未变。
