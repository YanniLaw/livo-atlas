# CBD Building 第二场景采样对照

将[Retail定额替换实验](gaussian-seed-replacement.md)的既有流程用于CBD_Building_01.bag。
目标是复验同一场景内resample/replace的覆盖保留、单块SSIM及共同深度取舍。
本轮运行既有代码和工具，不改变采样算法、默认配置或按画质调参。

## 输入与固定协议

bag为118.610003秒、1187帧图像、1187帧Livox点云、23988条IMU；话题为
`/left_camera/image`、`/livox/lidar`、`/livox/imu`。复用工程现有Avia/相机标定；
本轮未独立重新标定。Noetic完整rate1回放，前端2线程、位姿图线程池4线程、ROS执行器4线程。
固定CPU2/4/6/8/10/12，worker的OMP/BLAS为1，GPU任务顺序运行。

第一遍完整前端回放生成97关键帧，低于Retail固定预算研究使用的172帧。
按事前上限规则min(172,实际完整帧数)，使用全部97帧；不改变关键帧选择阈值。
按既有ID规则冻结85train/12heldout和12个预选query，训练每观测20步：每条件85次/1700步。
窗口10、每观测上限1000、每块上限10000，固定原生空间邻居、最终位姿、损失观测与留出隔离。
前端仍处理完整传感器流；heldout只针对高斯训练与评分，不是定位算法的留出数据。

第二遍完整回放创建有留出证明的最终Gaussian参考快照，逐字节核对第一遍冻结的图像/点云/帧记录。
随后空模型分别运行五种条件，各两个随机种子0/1：resample0%、resample25%、replace25%、
resample50%、replace50%。0%与uniform初始化等价。实验参数快照在首次画质评分前保存。

比较同一比例的两种方式，并比较原resample相对0%的变化。深度只在十次共同覆盖的同一参考像素上计算；
覆盖保留以对应随机种子的0%结果作共同基准。跨场景比较各自配对差值，不混合不同查询或深度交集。
GPU沿用4096MiB最小空闲显存与0.4分配器比例，输出至少保留1GiB磁盘；不复制bag或为每条件另存模型。

## 结果

十次有效试验、八组单变量比较与独立核验全部通过。每次85次训练/1700步、12个查询（10个联合）、
最终77000个高斯。固定的位姿、选块、观测和损失调度一致，产物摘要与各条件采样配额核验通过。
以下每个条件先按像素/窗口统计量汇总，再对两次重复取描述性均值；不是逐查询PSNR简单平均。

| 条件 | 联合PSNR(dB) | 联合SSIM | 联合覆盖 | 单块SSIM | 共同深度L1(m) | 共同深度RMSE(m) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| resample / 0% | 8.900956 | 0.168782 | 67.4705% | 0.170155 | 0.179185 | 0.849428 |
| resample / 25% | 8.950010 | 0.165001 | 69.2833% | 0.165920 | 0.196759 | 0.864904 |
| replace / 25% | 8.991503 | 0.159966 | 71.4771% | 0.160028 | 0.217200 | 0.894766 |
| resample / 50% | 8.999832 | 0.159630 | 70.8514% | 0.157823 | 0.237745 | 0.952177 |
| replace / 50% | 8.982276 | 0.151317 | 73.4521% | 0.146866 | 0.267925 | 0.988953 |

联合深度固定在十次共同覆盖的74604个像素上，占136346个有效LiDAR参考标签的54.7167%；
单块交集为79846/162748。两场景各有自己的查询、标签与交集，不能将绝对误差当成同一测试集合。
这里测的是高斯渲染深度，不能解释为SLAM轨迹误差；图像覆盖是image_mask内alpha≥.05的比例，
不等同于完整表面或纹理恢复率。

### 保留uniform原有覆盖

每次重复以自身0%结果为共同基准，统计`image_mask & (uniform_alpha >= .05) & (target_alpha < .05)`。
下表是丢失像素数，与replace/resample之间互相比较的覆盖周转量不同。

| 比例/重复 | 单块丢失：resample → replace | 联合丢失：resample → replace |
| --- | ---: | ---: |
| 25% / 0 | 353793 → 74811 | 281763 → 53934 |
| 25% / 1 | 357110 → 74380 | 283241 → 54317 |
| 50% / 0 | 326749 → 97808 | 255952 → 66830 |
| 50% / 1 | 326815 → 99125 | 255548 → 66554 |

两次uniform基准覆盖像素数：单块2366261/2366233，联合2186316/2186285。
按两次丢失数相加计算，25%替换减少79.01%的单块损失、80.84%的联合损失；
50%分别减少69.87%和73.92%。减少比例的分母是resample丢失数，不是全部基准覆盖数。

累计初始化85000个种子，包含之后随窗口淘汰的种子。25%两次替换17579/17587个，
保留67421/67413个uniform初始化位置；50%替换29524/29537个，保留55476/55463个。
这些是按真实配额与算法不变量推导的初始化位置数量，不是优化后高斯位置或最终渲染覆盖保证。

### 与Retail的配对效应对照

下表均为replace减去相同比例resample，两次描述性均值；深度各用本场景十次交集。
最后一列按两次原覆盖丢失数相加计算。

| 场景/比例 | 联合PSNR差(dB) | 单块SSIM差 | 联合覆盖差(百分点) | 共同深度L1差(mm) | 原联合覆盖损失减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Retail / 25% | +0.2054 | -0.001631 | +0.8862 | +1.30 | 74.70% |
| Retail / 50% | +0.1692 | -0.005400 | +0.7101 | +5.56 | 51.40% |
| CBD / 25% | +0.0415 | -0.005892 | +2.1938 | +20.44 | 80.84% |
| CBD / 50% | -0.0176 | -0.010958 | +2.6008 | +30.18 | 73.92% |

CBD25%相对resample的共同深度RMSE另增加约29.86mm；50%增加约36.78mm。
25%的联合SSIM在Retail小幅增加，在CBD下降约0.005035；50%的联合SSIM在两场景均下降。
单块SSIM下降和共同深度L1增加在两个场景、两个重复中均出现。覆盖保留收益可以复现，
但纹理/深度代价随场景变化，不能将Retail25%的联合质量折中直接推广到CBD。

已查看41号视角的25%/50%统一量程对照图。替换后点状支持区域变化，仍有大片空洞，
三角面板的连续结构和纹理没有被恢复。当前稀疏预算下图像质量仍低，不能以覆盖提高主张完成高质量重建。

### 系统、资源与验收

两次完整Noetic回放均正常退出，各1184次LIO/1183次VIO，输入传输/溢出拒绝均为0。
97套源资产逐字节一致，1184个轨迹样本的时间戳、位置及四元数分量最大差为0；
两次均处理10次回环任务、接受1次、最终位姿版本1。节点RSS峰值约804.12/834.92MiB。
这些是同环境行为复验，不是轨迹真值精度证明。

十次固定预算训练耗时12.73..13.23s，总评估28.33..29.45s，只作描述，不推断在线P95。
0%无覆盖预渲染，非零条件各75次。分配器allocated峰值约96.38..96.45MiB，reserved为112MiB，
不等于整机显存总占用；原始产物约3.2GiB，没有复制bag或每条件保存模型，结束时约20GiB空闲。

相机兼容修复后完整Python/CUDA372项通过，无跳过；准备流程7项及实际85个训练观测通过。
十次试验源代码指纹不变，全部评分浮点指标从归档样本重新计算一致，配置、位姿、源文件、
完整训练/损失ID、替换配额、图像/NPZ摘要、共同深度与uniform参考覆盖均独立核对。

默认仍保留uniform、coverage_sampling=resample和比例0.5。下一步继续诊断alpha覆盖与
纹理/多视图贡献、优化中的位置/尺度变化，先解释代价，再决定是否增加选择约束或调整训练。

## 跨电脑运行入口

先按[原生回放入口](spatial-heldout-comparison.md)用新bag生成独立关键帧参考，读取实际关键帧数。
在画质评分前生成该序列自己的split，不能复用Retail的split或位姿：

```bash
python tools/3dgs_probe/prepare_holdout_split.py \
  --dataset /data/cbd/frontend/keyframes \
  --preparer /sdk/bin/livo_atlas_prepare_3dgs_views \
  --input-file /data/CBD_Building_01.bag \
  --frontend-profile 'record actual ROS/build/calibration here' \
  --frame-count 97 --output /data/cbd/split.json
```

97是本机完整回放的观测数；其他环境应在评分前记录实际计数和预定前缀规则。
按上述原生回放入口创建带该split的最终参考快照，再按[固定预算入口](controlled-gaussian-sampling.md)
运行五条件/两种子。每个YAML保存相同的`evaluation.split_file`、预算、优化器和空间策略，
仅按条件改变`worker.coverage_sampling`与`worker.coverage_uncovered_ratio`。
相同比例的方法比较使用`--allow-coverage-sampling-change`，比例比较使用
`--allow-coverage-ratio-change`；两个开关互斥。所有输出使用新目录。

## 本轮发现的准备流程兼容问题

第一次固定预算试验在第二个子地图准备时停止，没有纳入结果。12个归档相机旋转的
正交/行列式误差略超过Python先前的1e-6阈值，最大约1.52e-6；原生归档与准备器接受1e-4，
随后投影回SO(3)。评分器在投影前使用更严格的wire位姿校验，造成两端不一致。
修复仅让归档相机按原生有限值/正交/右手容差校验后投影；明显非正交、反射和非有限旋转仍拒绝，
body/wire位姿校验不变。实际原生夹具回归测试经历RED→GREEN，所有CBD训练观测重新通过准备核验。
Retail原172个相机的投影矩阵与修复前逐元素完全一致；本轮全部十次有效试验使用同一修复版本。
