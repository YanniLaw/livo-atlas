# 全量深度候选与实际种子支持对照

2026-11-27。复用[覆盖诊断](gaussian-coverage-diagnostics.md)的四份冻结模型、选点、渲染及
训练前覆盖掩码，新增训练与渲染调用均为 **0**。默认参数、训练器、ROS 和算法核心均未改。
本轮在两个开发查询中发现：许多最终空洞附近有有效训练深度候选，但每帧1000点采样后没有
留下近邻。这支持先研究固定预算下的采样分布，尚不足以证明应增加点数或扩大窗口。

## 固定数据和定义

Retail 查询97、选块5/6，CBD查询9、选块0；每种子0/1沿用原率 coverage/replace25%，
1000点/帧、窗口10帧。原生 spatial selector 在同一参考快照选块，未用当前诊断权重重新排序。
从原生 preparer 重新读取选块的所有 train 观测，只用有效 image/depth mask；heldout 不参与候选。
每点按初始化的 float64 反投影及 float32 子地图存储约定重建，再用最终位姿变换到查询相机。

| 场景/块 | 训练帧 | 全部候选 | 窗口内候选 | 实际全部种子 | 实际保留种子 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Retail5 | 9 | 120858 | 120858 | 9000 | 9000 |
| Retail6 | 18 | 241191 | 133140 | 18000 | 10000 |
| CBD0 | 11 | 144259 | 131495 | 11000 | 10000 |

四组分别为 `input_all`、`input_retained`、`all_initial`、`retained_initial`。
只比较具有包含关系的四对：全量候选→全量种子、窗口候选→保留种子、全量候选→窗口候选、
全量种子→保留种子。不能把“全量种子→窗口候选”当成单一阶段链，也不能相加两种损失当作成因占比。
实际种子由已保存掩码重放选点，再与捕获XYZ/origin核验；本机四份重建最大差均为0。
每个半径、每个像素的四种支持计数均检查子集关系，数值边界破坏包含关系时拒绝发布。

查询像素按 `floor(u+.5)`，前方 z>1e-6，半径为整数圆 r=0/2/4像素。
有查询 LiDAR 深度时，点z与该目标像素深度比较，容差 `max(.05m,.02z)`，得到
consistent/front/behind；无深度不作表面判断。点邻域不是高斯足迹，也不是可见性测试。
分母固定为该模式**最终alpha<.05的有效图像像素**；初始种子仍是每颗点各自初始化时的位置，
不是同一时刻的一张未经训练模型。选点本身受历史训练覆盖反馈影响。

## 4像素邻域结果

下表是seed0/1各自比例的算术平均，未合并分子分母；每列都以该模式最终空洞数为分母。
单块只用owner块，联合使用参考选出的两块。

| 模式 | 全量候选附近 | 窗口候选附近 | 全量种子附近 | 保留种子附近 | 窗口候选有/保留种子无 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Retail单块 | 76.780% | 76.359% | 10.399% | 3.944% | 72.416% |
| Retail联合 | 76.137% | 75.876% | 8.884% | 4.001% | 71.875% |
| CBD单块 | 80.200% | 80.200% | 7.043% | 6.591% | 73.609% |

候选窗口移除造成的“原有近邻完全消失”分别占空洞0.421%、0.261%、0%；
实际种子窗口移除的对应比例为6.456%、4.883%、0.452%。
**这些数值衡量指定空洞的邻域支持损失**，不衡量所有候选点的淘汰比例或地图总体质量。
窗口移除也可能减少数量而不让邻域支持归零，因此CBD的0%不代表其窗口没有移除数据。

原始计数与独立已知深度子集如下，顺序均为seed0/1。

| 模式 | 最终空洞 | 有查询深度空洞 | 窗口候选有/保留种子无（全部空洞） | 同一对比失去深度一致支持（已知深度空洞） |
| --- | --- | --- | --- | --- |
| Retail单块 | 86360 / 86008 | 2295 / 2269 | 62485 / 62336 | 1923 / 1884 |
| Retail联合 | 84095 / 82955 | 2237 / 2187 | 60493 / 59575 | 1873 / 1811 |
| CBD单块 | 112276 / 113390 | 3521 / 3672 | 82612 / 83499 | 2805 / 2973 |

全量候选在已知深度空洞的一致支持比例分别为87.706%、87.383%、85.299%；
窗口候选→保留种子失去一致支持的比例为83.412%、83.268%、80.314%，
分母仅为各自约2.6%–3.2%的有深度空洞。约97%的未知部分不能套用这些几何结论。
front_only/behind_only/mixed/none 的互斥完整计数保存在每份 report；未把不一致点计为表面支持。

## 半径敏感性与判断边界

| 模式 | 全量候选附近 r0/r2/r4 | 窗口候选有/保留种子无 r0/r2/r4 |
| --- | --- | --- |
| Retail单块 | 7.280 / 49.809 / 76.780% | 6.154 / 47.954 / 72.416% |
| Retail联合 | 6.843 / 48.616 / 76.137% | 6.007 / 47.242 / 71.875% |
| CBD单块 | 6.832 / 51.911 / 80.200% | 6.751 / 51.779 / 73.609% |

结果明显依赖邻域半径。相邻输入点可能属于不同表面、遮挡或动态目标；未知深度处尤其不能
把附近候选视为可直接填补空洞的点。最终空洞条件也会偏向缺少种子的位置：不透明度/足迹
本身会让近中心像素较少进入空洞分母。这不是独立的“点数不够”证明。
本轮只是输入空间与实际采样空间的可用支持对照，没有用更多种子训练、没有重渲染，也没有
证明RGB、SSIM、共同深度误差或实时性会改善。不能外推到全图、长路线或其他相机。

## 复现与验收

```bash
python tools/3dgs_probe/diagnose_depth_candidates.py \
  --diagnostic-directory /data/coverage-Retail-0 \
  --map-directory /data/reference/gaussian --keyframes /data/reference/slam/keyframes \
  --prepare-executable /sdk/bin/livo_atlas_prepare_3dgs_views \
  --selector-executable /sdk/bin/livo_atlas_select_gaussian_neighbor \
  --output /data/candidates-Retail-0
```

使用同一coverage归档及参考源，seed1和CBD同理。输出必须为新目录；原有report、全部产物收据、
split、最终poses、源资产、相机、原生空间选块及运行库均重新校验。跨电脑可重新产生对应覆盖
诊断；已归档report中的来源路径需与实际源一致，本入口不提供路径重映射。
这里只使用CPU（研究运行设置 `CUDA_VISIBLE_DEVICES=''`），不启动训练或渲染。

每帧最多100万像素、每块最多32主观测、最多两块；投影按≤64000点分块累计int32计数。
counts.npz仅保存每块全量/窗口候选的r0/2/4四类计数；种子计数从原捕获值复算。
输出受64MiB与源YAML预算共同约束，写出前按原始计数数组预算拒绝超量输入；
准备临时空间另计，磁盘预留至少1GiB。待发布报告写入后重验其内容、输出和所有输入，
检查原生运行库解析和空间，再原子rename；失败目录只有failure.json而无成功report。

完整Python/CUDA回归 **419/419**，无跳过，154.377秒。新增8个测试覆盖分块、手算坐标/分母、
非法子集、来源/种子变更、磁盘下降及待发布阶段的输入/产物/报告/运行库变化。
独立审计重新准备原始观测、反投影，并用另一份 `bincount` 实现重算所有像素支持，
四份的输入计数、所有统计、源绑定及全部收据完全一致。无新增GPU调用。

工作区 `validation/depth-candidate-support-20261127/` 保存冻结协议、四份结果、独立审计脚本、
日志及summary.json，约5MiB；复用既有约65MiB覆盖归档，没有复制bag或完整地图。
