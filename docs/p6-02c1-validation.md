## 同一数据集的离线几何验证

两端输入固定为 P6-02b Noetic 版本 0 关键帧数据集的同内容副本，含 172 帧、13 个封存子地图。
设计时只读检索有 22 对粗候选，每查询最多 5 对后留下 20 对。

| 项目 | Noetic / PCL 1.10 | Humble / PCL 1.12 |
| --- | ---: | ---: |
| 几何通过 / 重叠不足 / 未收敛 | 8 / 10 / 2 | 8 / 10 / 2 |
| 输入文件前后摘要一致 | 703 | 703 |
| 固定引用体素峰值 | 31,295 | 31,295 |
| 采样进程 RSS 峰值 | 97.32 MiB | 96.30 MiB |
| 进程壁钟时间 | 2.890 s | 3.084 s |
| 每对计算耗时中位数 / 最大值 | 84.32 / 110.37 ms | 96.05 / 130.15 ms |

两端均使用安装后的 `bin/livo_atlas_verify_loops`，实际采样到回环库及其依赖。
结果在 `retail-noetic-final/` 与 `humble-evidence/retail-humble-final/`。`summary.yml` 记录全部参数、计数及 complete，
`matches/*.yml` 保留每对初值、正反迭代与变换、独立质量和拒绝原因。
两端输入的 703 个文件逐个摘要相同，20 对分类也逐对相同；数值和迭代次数保留各版本原始结果。
通过的 TARGET-SOURCE 为 0-11、0-12、1-11、2-10、2-11、3-10、3-11、4-9。
每块临时配准云为 1,855–3,551 点。配准点数是 0.5 m 粗化后的点数；质量检查使用原 0.2 m 几何体素，二者不可混称。

这些是当前阈值下的几何证据。单段约 135 秒、没有回环真值的 bag 不能证明准确率、召回率、
长距离漂移鲁棒性或在线 3DGS 的可用性。重复结构可能产生双向一致的错误匹配。
缓存三块和逐候选处理不构成固定 RSS 上限；PCL 临时状态与共享引用仍占内存，也无壁钟硬截止。

## 审阅、修复及边界

一次独立整分支审阅覆盖 `3464728..497702e`，结果为 Critical 0、Important 1、Minor 3。
重要问题是 float 有限值仍可能在 PCL 乘积和平方距离中溢出。已复现失败（包括退出 139），
在 `64054a7` 将原坐标、双向初值和后续 GICP 更新限制在保守算术包络内；对应回归与
完整 39/39 核心测试通过。该上限防止溢出，不保证极大坐标下仍有配准精度。
修复后按执行流程没有再次发起独立审阅；平台测试由执行者实际运行。

三个小问题延期记录：

1. 部分不可能满足的点数配置关系会得到候选拒绝，尚未全部提前作为非法配置拒绝。
2. 失败测试在首个匹配前触发，未直接覆盖前序匹配记录保留及损坏数据集元信息。
3. 每对报告尚未单列原始诊断体素数。

验证过程中的环境与脚本问题均保留失败记录：ROS 网络接口枚举被沙箱拒绝后使用已授权权限；
回放脚本入口误触源码保护检查后恢复正确入口；进程采样发现 psutil 缓存启动器 exe，
通过小复现确认后改读 `/proc/PID/exe` 并重跑。上述问题未修改冻结产品代码。

本工具面向单一所有者的离线数据集，不提供敌对并发文件修改或掉电事务持久性保证。
C1 输出不能直接当作图准入决定；C2/C3 的协议、在线调度、全局发布及 Gaussian mapping 仍需后续设计。

## 复核入口

阶段目录中的 `check_final_evidence.py` 汇总六组 SDK、八组 ROS、八次回放和两次离线工具，
复核 XML、安装消费者、节点库采样、输入资产与源码归档，结果写入 `final-evidence.json`。
`compare_replays.py` 逐项比较本阶段与 P6-02b 的同环境结果，输出每次的 `strict-checks.json`。
`run_verifier.py` 的实际证据是各工具输出目录中的 `run-evidence.json`，包含逐文件 SHA256、
实际加载库、CPU/OMP/nice、RSS 和耗时。脚本及本机绝对路径属于阶段证据；跨电脑需按环境改路径。

产品代码冻结后只更新本文、使用说明、文档索引与计划状态；没有为提高通过率修改默认阈值。
