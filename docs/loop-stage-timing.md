# 回环分段计时

本文历史时间包含线程审计探针开销，不能直接代表日常性能。
后续 CPU 采样定位到该干扰，见 [不加载线程探针的对照](gicp-cpu-profile.md)。

在 `config/backend.yaml` 中设置 `diagnostics.stage_timing: true`。ROS1、ROS2
和 SDK 的 `SystemOptions::stage_timing` 使用同一开关。默认关闭，新增计时点关闭时
不读时钟、不打印阶段日志。同步 `LoopClosure::Run()` 沿用原协议；本记录的新增查询计时
针对 PoseGraph 的原生异步路径。

日志沿用 `livo_atlas timing stage=NAME seconds=VALUE`，既有回放工具会自动汇总
到 `summary.json` 的 `stage_timing_seconds`。累计耗时需从 mapping.log 逐条求和，
不要将中位数乘次数当作累计时间。

| 阶段 | 测量范围 |
| --- | --- |
| loop_query_prepare | 验证派发元数据、检索候选 |
| loop_geometry_read | 获取一块几何，包含版本切换、缓存访问与必要的完整构建 |
| loop_cloud_read | 完整构建中的已提交原始位姿、时间戳及点云读取与校验 |
| loop_geometry_build | 完整构建，包含读取、体素累计、快照及缓存替换 |
| loop_geometry_snapshot | 完整构建中的几何快照生成 |
| loop_prepare_batch | 一批候选所需的源/目标几何准备 |
| loop_candidate | 单个 VerifyLoop 调用，包括异常返回 |
| loop_verification_batch | 几何准备结束至依赖汇总任务开始，包括验证任务排队 |
| loop_admission | 候选筛选、私有图试算和优化后复核 |
| loop_graph_build / loop_solve | 原有 GTSAM 建图和求解计时 |
| loop_geometry_recheck | 预览位姿生成及新旧回环的几何复核 |
| loop_query_compute | 注册任务图至最终任务调用完成回调前，包括池内排队 |
| loop_result_queue_wait | 完成回调进入至串行完成工作项开始，包括独立 LoopBackend 等待 Poll |
| loop_result_acceptance | 串行完成工作项中的判定、日志及必要的位姿提交 |
| archive_publication_wait | 归档发布至 owner 回执，包含交付、回调和回执调度开销 |
| loop_pose_delivery_latency | 仅已接纳回环：提交查询到线程池之前至 owner 应用位姿并完成回调后的回执 |
| loop_pose_publication_wait | 同一回环优化位姿发布至 owner 回执；回执时采样，再恢复队列 |

上述时间相互包含。读取和快照属于完整构建，几何准备属于查询计算，几何复核属于接纳试算。
并行候选各自耗时的和与批次墙钟时间含义不同。结果接纳与发布等待也可能重叠，
不能相加后当作端到端耗时。原有 `loop_optimization_result_latency` 在 Classify 中采样，
未包含其后的验证、提交和 owner 交付。
两个 loop_pose 指标只记录成功回执的回环位姿，不包括普通关键帧、封口、外部位姿更新或
拒绝查询；回调失败不产生成功交付样本。它们不表示 ROS 接收者或 GPU worker 已处理结果。
派发时间在最终检查的锁内、Schedule 之前采样，避免漏记提交和提前开始的任务耗时。

成功几何读取在同一开关下输出 loop_geometry_cache，区分读取器重建、完整构建、云读取、
驱逐和驻留块数。它是缓存诊断日志，不是另一个可相加的计时阶段。
当前无探针归因、边界验证和结果见 [几何准备与优化位姿交付](geometry-delivery-timing.md)。

每个批次消费一次时间戳；因前一批出错而跳过的批次不会产生验证时间。
异常中止时不保证所有子阶段都有样本。发布等待包含回执调度和解锁后的采样开销，
不适用于精确分析微秒级回执成本。

实现不修改候选排序、优化判定、Task 依赖或归档格式。

## Retail_Street 验证结果

本机 Noetic，前端预算 2、后台线程 4、几何驻留 3，完整回放约 135 秒。
SDK 76 个 CTest 目标、Noetic 3 个相关目标、Humble 5 个相关目标通过。
开关测试覆盖正常提案；多批次读取失败测试先复现重复计时，再验证跳过批次不计时。

完整回放产生 1352 次 LIO、1351 次 VIO、172 个关键帧、13 次查询、20 次候选验证及
2 次接纳，最终版本为 2。原始帧、成员修订、轨迹和语义输出与上一版字节一致，
去掉耗时后的候选诊断一致；最终位姿差低于 1e-12，归档检查为 consistent。

| 查询内的主要阶段 | 累计墙钟时间 | 占查询计算时间 |
| --- | --- | --- |
| 几何准备，12 批 | 1.346 s | 7.1% |
| 候选验证批次，12 批 | 14.652 s | 76.8% |
| 接纳试算与复核，13 次 | 3.083 s | 16.2% |
| 查询计算，13 次 | 19.081 s | 100% |

接纳试算中，优化后几何复核累计 3.077 s，GTSAM 建图与求解仅约 5.16 ms。
所有几何读取累计 1.627 s，其中完整构建 1.590 s，读取原始数据 0.334 s，
快照生成 0.187 s。这些读取还包含优化后复核的重新构建，不能与上表直接相加。
20 个单候选耗时合计 22.756 s，存在实际重叠，不能作为串行基线或直接宣称加速比。

13 次结果排队累计 0.236 ms，最长 0.082 ms；串行接纳累计 30.3 ms。
175 次归档发布等待累计 1.445 s，最长 43.3 ms，包含普通关键帧发布，
不能全部归因到回环。单次完整回放只能定位本机当前配置的主要耗时，不能代表长序列性能。

下一步先细分 VerifyLoop 的输入准备、正向/反向 GICP 和几何质量计算，
同时检查优化后复核的质量计算。依据结果再选择复用搜索结构或协方差等工作，
保持候选顺序与质量阈值。当前数据没有支持优先更换优化器或扩大几何缓存的证据。

证据位于 `validation/loop-stage-timing-20261124/`，包括 analysis.json、完整回放、
构建日志和失败路径测试。计时开关关闭时不输出新增阶段；不改变数据集格式。
