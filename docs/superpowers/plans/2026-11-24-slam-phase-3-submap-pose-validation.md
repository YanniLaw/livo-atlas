# SLAM 位姿提交校验实施计划

这一批实施 3.1 的第一步。在一次位姿提交中复用同一对旧、新快照的校验结果，使完整快照的扫描次数与子地图数量无关。单块比较继续校验传入的原始快照。 [异步位姿图设计](../specs/2026-11-24-slam-engineering-optimization-design.md#31-减少重复校验和历史复制)

- [x] 扩展现有单块比较和存档测试。用同样的 64 个关键帧构造 2、8、32 块子地图，核对成员和锚点、跨块支持帧、提交版本，以及无效提案后的继续提交。单块测试覆盖子地图范围之外的无效位姿和快照覆盖不一致。
- [x] 在本机共享库构建上统计成功提交调用 `ValidatePoseSnapshot` 的次数和扫描的位姿数。先用当前版本复现次数随子地图数量增长。
- [x] 在 `src/mapping` 内复用一对只读快照的比较上下文。构造时校验快照和共同前沿，每次比较继续检查本块成员并计算锚点相对位姿。由 `OnlineSubmapManager` 在读取成员记录前创建一个上下文，并按子地图 ID 顺序读取、比较和提交。原有归档校验和异常处理沿用当前入口。
- [x] 重测扫描次数，运行相关 SDK 回归，再以同配置回放 Noetic 的 10 秒片段和完整 `Retail_Street.bag`。对照前端轨迹、关键帧、回环提案与位姿归档。
