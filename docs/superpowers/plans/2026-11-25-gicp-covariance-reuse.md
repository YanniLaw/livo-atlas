# GICP 协方差剖析与局部复用

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans.

目标是区分协方差与迭代成本，并在数值结果不变的前提下复用同一候选的正反向协方差。
沿用当前开发分支与已有本地提交授权，不修改公共 API、匹配参数、阈值或归档格式。
依据 docs/loop-verification-reuse.md 的后续方向实施。

- [x] 先添加 GICP 细分计时的开关测试并确认失败。
- [x] 在现有私有 Gicp 子类中使用 PCL 原始 computeCovariances 算法，测量源树、两组协方差、迭代整体、估计器和变换安全检查。计时关闭时保留 PCL 原始计算路径，所有新增计时关闭时不读时钟。
- [x] 完整 bag 建立有计时、无复用基线，验证数学诊断和资产不变。
- [x] 以重复计算次数为失败用例，复用同一候选的两个协方差数组；反向交换角色并在 setInput 后设置，保留两个独立求解器，质量计算前释放数组。不跨候选共享。
- [x] SDK、Noetic、Humble 测试，完整 bag 配对对照与独立源码复核，记录结果并本地提交。

复核重点是 PCL 1.10/1.12 初始化顺序、协方差数组与点序绑定、参数一致性、输入未被原位改写、失败/迭代上限路径、数组生命周期和开关关闭路径。PCL 基类仍负责迭代和收敛；计时重载先准备协方差后调用基类，基类再次初始化源树时已是缓存命中。指标包含关系需明确。

证据目录 validation/gicp-covariance-20261125。空间成本为在两个方向之间保留两个数组，公共下采样上限各20000点时合计约2.88MB。完整 bag 不能替代长序列效果验证。

实现、验证结果与计时限制见 [复用记录](../../gicp-covariance-reuse.md)。
