# 位姿图线程池配置实施计划

目标是让 `LivoSystem` 内的位姿图线程池支持 YAML 配置，默认 4 个工作线程，并验证 6 个工作线程。参数为 `pose_graph.num_background_threads`，独立 SDK 对应 `SystemOptions::num_background_threads`。沿用当前开发分支实施并进行本地提交。

## 调度约定

存档、图状态变更和提案接纳由同一条 `WorkQueue` 执行线处理。回环查询作为线程池任务使用派发时的自有快照，结果回到该队列接纳。增加线程数后，回环计算与存档能够同时推进。参数为正整数，1 线程用于确定性回归，4 和 6 用于常规运行与并发验证。等待和 join 由系统调用线程承担。

## 实施步骤

- [x] 在现有回环测试中加入 4 和 6 线程场景，阻塞回环任务并验证后续关键帧可写入、输入可封存。补充无效线程数在 I/O 前拒绝的检查，先确认测试在现有代码上失败。
- [x] 添加 SDK 选项、共用参数读取及 YAML 默认值，用选项构造 `PoseGraph` 的 Cartographer `ThreadPool`。启动时通过 GLOG 记录线程数。已有单线程队列测试显式选择 1 线程。
- [x] 验证部分线程创建失败时的资源回收。在独立进程注入第三次 `pthread_create` 失败，确认回收前两个线程后向调用方报告原始异常。
- [x] 在 Noetic、Humble 验证缺省值、4、6、0 和负数的参数读取，运行回环生命周期、存档和相关输出测试，验证安装后的 SDK 消费。
- [x] 固定前端 OpenMP 预算及同一组可用 CPU，以 1、4、6 线程回放现有 `Retail_Street.bag`，比较前端输出、最终位姿、回环记录和归档状态。记录队列等待与回环延迟。
- [x] 独立复核并记录结果。

本次调整线程池配置与并发交接。候选验证的进一步拆分使用后续独立实施计划，复用同一线程池和 `Task` 依赖。

## 验证记录

独立 SDK 的 76 个 CTest 目标、4 个安装后消费者通过。Noetic 的 9 个核心 CTest 目标和 39 个 ROS 测试用例通过，Humble 的 4 个相关 CTest 目标通过。回环生命周期测试连续重复 10 次通过。

三组完整 bag 回放均使用 CPU 集合 `2,4,6,8,10,12`，前端 `OMP_THREAD_LIMIT=1`。各组输出 1352 次 LIO、1351 次 VIO，原始关键帧、成员修订和轨迹字节一致。归档检查全部返回 0，每组都有 172 个关键帧、13 次已完成的回环查询及 2 次接纳。最终位姿的最大绝对差为 0。

| 后台线程数 | 本次回放的归档队列最长等待 |
| --- | --- |
| 1 | 161.38 ms |
| 4 | 2.18 ms |
| 6 | 0.147 ms |

部分线程创建失败的探针在原实现中触发 `SIGABRT`，修复后回收前两个工作线程并捕获 `std::system_error`。独立代码复核确认图状态仍由串行执行线持有，阻塞回归测试增加了超时失败路径。

工作区证据位于 `validation/pose-graph-threads-20261124/`，包括 `thread-comparison.json`、`thread-startup-red.json` 及各构建和测试日志。
