# SLAM 几何子地图增量通知实施计划

这一批把局部几何缓存和全局地图输出接入 3.1 的增量通知。追加与封存只更新活动子地图及其相邻边界。回环提交按新位姿版本比较已经构建的相对位姿，决定保留体素数据或重建。完整快照接口仍供独立调用和旧读者使用。 [增量通知首批](2026-11-24-slam-phase-3-incremental-submap-notifications.md)

## 局部几何

- [x] 固定测试数据对照全量与增量路径。覆盖主成员追加、支持帧边界、先校验整批再提交、缓存淘汰、刚性修正复用和组内位姿变化后的重建。
- [x] 复用已有尾部位姿计算。通过新一帧的修正位姿、前沿和本轮成员修订更新 `GeometryMapper`。用最后一次完整快照与分段保存的新增位姿提供索引。每轮只规划受影响的成员，缓存统计和淘汰只查询驻留块。
- [x] `OnlineSubmapManager` 在追加和封存时交付局部增量，在位姿提交时交付已校验的完整快照。在只有增量消费者的会话中，局部几何的存在也允许追加跳过完整历史物化。

## 全局几何

- [x] `GeometryMapOutput` 记录成员修订和前沿，在实际派发时成对捕获对应的位姿快照与关键帧读取视图。状态超限、启动和收尾先读前沿，工作线程继续使用固定的自有输入。核对合并后的帧数、位姿版本和几何结果。
- [x] 共享 `main` 将全局几何接到增量回调，并保留几何的完整通知入口及其同版位姿检查。在线 3DGS 的快照消费单独迁移。

## 验收

- [x] 测量已有 256、512、1024 和 4096 个关键帧时单次追加的全量校验和遍历位姿数。每块成员数和驻留限额固定，分别记录版本提交与实际发布所需的完整快照。
- [x] 构建 SDK、Noetic 和 Humble 并按相同配置对照 10 秒和完整 `Retail_Street.bag`。核对局部几何计数、全局地图消息、关键帧与回环存档，记录实际调度差异后在当前分支提交。

## 追加测量

对照基线为 `7f3647c`。合成序列开启回环、局部几何和全局几何，每块 16 个主关键帧，局部缓存限额为 2 块。表中操作均为跨块追加，测量范围是此次追加及同步通知。

| 追加前关键帧数 | 全量位姿校验次数（前 → 后） | 遍历位姿数（前 → 后） | 成员校验次数（前 → 后） |
| ---: | ---: | ---: | ---: |
| 256 | 3 → 0 | 514 → 0 | 21 → 4 |
| 512 | 3 → 0 | 1,026 → 0 | 37 → 4 |
| 1,024 | 3 → 0 | 2,050 → 0 | 69 → 4 |
| 4,096 | 3 → 0 | 8,194 → 0 | 261 → 4 |

单独测试派发和优化提交时，首次派发捕获 4,097 条位姿。优化提交走完整校验，随后派发直接使用附带的已提交快照。探针记录的是同步执行者的校验量，发布工作线程会验证自己的任务输入。

## 回放和测试

- Noetic 使用逻辑 CPU 2、OpenMP 单线程和 1× 播放速度，开启局部几何、全局几何及回环。10 秒对照各有 98 次 LIO 和 97 次 VIO，3 份地图逐点一致。
- 完整回放各有 1,352 次 LIO 和 1,351 次 VIO，轨迹、前端记录、ROS 点云和图像载荷、516 个关键帧资产、185 份成员记录及两份正式位姿文件一致。13 个回环查询的结果一致，分别接受 2 条回环，归档检查均确认位姿版本 2。
- 全局地图两次各收到 28 份。异步派发时刻不同，18 个相同位姿版本、帧数与成员修订的样本均逐点一致。两次最终观测都包含 172 个关键帧、13 个子地图和 100,000 个显示点。另一次 10 秒回放同时启用轨迹和几何地图，两个输出均收到有效消息。
- 独立 SDK 全部 76 个 CTest 目标通过。Humble 通过 11 个相关 CTest 目标，Noetic 通过 62 个相关用例。覆盖增量与全量局部结果、错误修订回退、合并派发、位姿前沿不匹配和资源超限时的最终封存。

两侧使用相同的选项，把 `--workspace` 和 `--output` 分别指向各自的源码及二进制快照和输出目录。短回放将 `--duration` 设为 10。

```bash
OMP_THREAD_LIMIT=1 OMP_NUM_THREADS=1 python3 tools/run_baseline.py \
  --workspace /path/to/snapshot --bag /path/to/Retail_Street.bag \
  --output /path/to/new-result --duration 136 --rate 1 --cpu-affinity 2 \
  --image-queue-size 32 --semantic-output --geometry-submaps --geometry-map \
  --loop-closure --stage-timing
```

本机摘要 `verification-10-136.json`、探针和日志位于工作区的 `validation/slam-incremental-geometry-20261124/`。

## 复核边界

- 两个 SDK 观察入口分别验证。同一实例切换通知格式时，过去只收到增量的位姿前缀缺少完整校验。
- 独立使用 `GeometryMapper` 时，若新块构建抛出异常，上一封存块的构建器会留至淘汰或完整更新。`LivoSystem` 仍按既有规则终止此类失败的会话。
