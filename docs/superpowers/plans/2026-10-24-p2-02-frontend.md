# P2-02 Frontend 执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将共享前端状态及实际 IMU/LIO/VIO/地图调用迁入具体 Frontend，ROS 消费更新结果。

**Architecture:** 普通 FrontendOptions 配置私有实现；Frontend::Process 操作同一同步输出并返回状态值快照/只读点云视图。P2-01 同步保持独立；ROS 发布不再清理前端内部世界云。旧视觉/地图发布通过借用过渡口继续运行。

**Tech Stack:** C++17、Eigen、PCL、OpenCV、现有 IMU/VIO/体素地图、Noetic、GTest、Python。

**Spec:** `docs/superpowers/specs/2026-10-24-p2-02-frontend-design.md`。

## Global Constraints

- 当前 refactor-fast_livo2 分支实施，基线 f77ae4871b9f72a469918ea6a5617db6067566d8；不合并/推送或新增执行确认。
- 仅 livo-atlas；vikit 固定 6c886c8e5d83997806e00294826d528cea3581dd。
- Google C++17；不复制估计状态或算法实现，不引入虚拟组件/阶段回调/事件总线。
- 保留数值公式、double 秒/curvature 毫秒、首帧锚点、EOF 门控、时钟回退处理、特征 disB 和驱动单位。
- 旧算法内 ROS/vikit/I/O 暂留；公开头必须无 ROS/vikit 编译。不得宣称整个 Frontend 已无 ROS。
- 构建 nice -n 10、-j1，与回放串行；ROS 构造/运行使用独立副本且无 RViz。
- 证据 validation/P2-02-noetic-20261024；参考复用必须逐项校验源/程序/全部库/bag/环境/参数；有效导出结果零容差。

## Review Focus

1. 初始化/空点云时 prediction 日志仍有一行，updated=false 不发布/写更新后状态；测试实际 LIO 初始化。
2. VIO 和 LIO 必须指向同一个主状态，传播先验地址不能因 Frontend 生命周期移动而悬空；真实组件绑定及两实例独立用例验证。
3. 发布移到地图更新后不得改变状态值、点云坐标或输入/更新次数；两组完整导出对照验证。
4. VIO 世界云清理必须由 Frontend 完成，发布可省略；核心连续调用/空视觉用例和完整 bag 验证。
5. 实际 imu_cbk 的 double 覆盖元数据和最终样本舍入时间不同，回退不得改写有效队列；真实 ROS 用例补齐 P2-01 延期项。
