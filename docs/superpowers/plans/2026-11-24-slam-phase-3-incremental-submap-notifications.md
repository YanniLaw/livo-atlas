# SLAM 子地图增量通知实施计划

这一批为 3.1 建立增量通知，首批接入系统内的回环协调和关键帧轨迹发布。追加与封存交付新增观测、成员修订和当前位姿前沿。提交回环时一并交付该版本的不可变位姿快照和各块位姿变化。SDK 的完整快照查询及逐次回调沿用现有合同。 [异步位姿图设计](../specs/2026-11-24-slam-engineering-optimization-design.md#31-减少重复校验和历史复制)

## 任务 1 建立两类通知

- [x] 用现有管理器测试验证增量与完整回调并存。以两条追加、一次封存和一次位姿提交检查通知顺序、前沿以及随提交交付的完整快照。在只注册增量回调时，异常的旧版外推位姿仍应在追加时终止会话并保留已提交资产。
- [x] 在 `OnlineSubmapManager` 生成 `OnlineSubmapDelta` 和 `PoseFrontier`。只向需要完整历史的现有消费者或位姿提交物化快照。在增量追加中验证新尾部的位姿，复用现有投影和校验。全量回调与增量回调可分别在首帧之前注册。

## 任务 2 迁移回环与关键帧轨迹

- [x] `LoopBackend` 按前沿和成员修订收集元数据。派发和结果验收需要读取完整前沿时，由系统所有者取得与已观察版本匹配的快照。保留接受全量更新的 SDK 入口及排队规则。
- [x] `TrajectoryOutput` 接收增量前沿，合并待发通知。系统所有者在派发给轨迹工作线程前捕获位姿和文件读取视图，检查版本及帧数。初始化和收尾也先读取前沿，超预算时交付现有的限额状态。
- [x] 共享 `main` 为轨迹注册增量回调。几何输出和在线 3DGS 的成员缓存及版本校验作为各自的迁移批次。启用这些完整快照消费者的会话仍按现有契约提供完整数据。

## 任务 3 验收

- [x] 用 256、512、1024 和 4096 个历史关键帧测量同一活动子地图阶段的追加。记录全量快照校验次数、遍历位姿数及耗时。在已迁移的配置中，未派发后台任务的追加轮次只检查新数据。另测全量回调启用时的兼容行为。
- [x] 验证回环前沿、轨迹合并、归档终止和无效快照的行为。构建独立 SDK、Noetic 和 Humble。按前一批的回放设置核对 10 秒和完整 `Retail_Street.bag`，另运行开启关键帧轨迹的短回放核对发布前沿。

## 追加测量

合成用例启用回环和关键帧轨迹，每块 16 个主成员。探针只统计单次追加及其同步观察回调。位姿数为该次操作在 `ValidatePoseSnapshot` 中检查的元素总数。正常派发仍按需要捕获一次完整前沿。

| 追加前关键帧数 | 原遍历位姿数 | 增量路径遍历位姿数 | 同时注册完整回调时的遍历位姿数 | 原追加耗时 ms | 增量追加耗时 ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 256 | 514 | 0 | 257 | 0.093 | 0.102 |
| 512 | 1,026 | 0 | 513 | 0.172 | 0.135 |
| 1,024 | 2,050 | 0 | 1,025 | 0.184 | 0.179 |
| 4,096 | 8,194 | 0 | 4,097 | 0.592 | 0.367 |

增量路径的各规模都记录到零次全量快照校验。表中耗时是单次样本，包含关键帧和成员写入，也受向量扩容影响。对已有 4,097 个关键帧、预算为 1 的轨迹输出，初始化和收尾合计从 4 次全量快照校验降为零次，并交付资源超限状态。

## 回放与回归

- 独立 SDK 通过 11 组 CTest，Humble 通过 10 组 CTest，Noetic 通过 34 项针对性测试。覆盖增量和全量通知并存、投影尾部、失败保留已提交位姿、轨迹合并及位姿前沿不匹配。
- Noetic 在逻辑 CPU 2、OpenMP 单线程、1× 速度回放。10 秒对照各得到 98 次 LIO、97 次 VIO。完整回放各得到 1,352 次 LIO、1,351 次 VIO，轨迹、前端记录、ROS 载荷和 516 个关键帧文件一致。13 个回环查询与 2 个预提交记录的语义字段一致，两份正式位姿文件逐字节一致。归档检查确认位姿版本 2。
- 开启关键帧轨迹的 10 秒对照中，两侧各收到 6 份轨迹通知，最终交付版本 0、5 个关键帧。最终轨迹内容和对应 Path 与基线一致。
