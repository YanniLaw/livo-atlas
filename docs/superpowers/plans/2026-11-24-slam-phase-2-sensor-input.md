# SLAM 传感器入口交接实施计划

这一批落实 2.3 的传感器交接。保留共用 `main` 和两端的多线程执行器。Noetic 由主循环处理传感器和传播，Humble 由现有互斥回调组处理。 [总设计](../specs/2026-11-24-slam-engineering-optimization-design.md#23-缩短-ros-持锁路径)

- [x] 让两端在转换后向共用入口移交数据。入口按实际入队顺序读取，每类消息沿用 `sensor_buffer` 的数量上限。修正后的时间跨度仍由算法队列检查。禁用流在订阅处过滤，双 ROS 通过 `qos` 设置各自的传输深度。
- [x] 每轮最多从入口取 32 条消息，执行一次同步。保持 `driver_fix` 的 LiDAR 锚点顺序、传播的调度时钟和等待时的后台轮询。结果和对应地图修正在同一轮从系统所有者发布，借用的前端视图在这一轮用完。之前测得的发布开销低于 0.2 ms，先测量这一轮改动带来的变化。 [阶段计时](2026-11-24-slam-phase-2-timing-and-path.md#实施与验收记录)
- [x] 执行器停下后关闭入口，由系统所有者消费仍能同步的输入。断开 ROS 后继续完成存档。任何入口超限都保留首次异常并记录失败。收尾记录入口峰值、入口与算法队列采样峰值、剩余量和各类拒收。对照回放预期条数与节点接收条数衡量传输差异，并记录中间件能够上报的丢失。
- [x] 先确认订阅直接修改系统的回归测试失败，再验证顺序、分类容量、关闭、失败收尾以及暂停期间的后台轮询。完成独立 SDK、Noetic 节点和 Humble 节点构建测试。使用 `Retail_Street.bag` 对比轨迹、关键帧、回环和入队等待。

## 实现约定

- 批次遇到可能超过算法队列数量或修正时间跨度的下一条输入时，先尝试同步一次。同步处于等待时，按原顺序提交这条输入，由算法继续执行原有边界检查。收尾优先处理就绪数据，随后逐条接收剩余入口数据。
- Noetic 的传播时机仍由 ROS 时钟驱动，定时回调向主循环发出请求。Humble 在互斥处理回调内检查单调时钟上的 4 ms 周期。单次耗时较长的前端更新会延后这一轮的传播。
- 回放同时记录估计更新数和 ROS 发布数。Noetic 记录同一连接上可观测的连续序号缺口，Humble 使用中间件支持的丢失事件。序号缺口和事件计数覆盖各自可观测的范围，完整回放另用 bag 条数核对节点实际接收量。
- `combined_sampled_peak` 是入口与算法缓冲在处理轮次采样时的合计最大值。IMU 计数包含为传播保留的样本副本。停机时的 `system_pending` 包含缺少同步条件的余量。

## 验收记录

- 独立 SDK 的 5 组 CTest、Humble 的 6 组 CTest、Noetic 的 43 个 ROS 测试和回放工具的 40 项测试通过。共用入口的 7 项测试覆盖 FIFO、`driver_fix` 锚点、单轮预算、较小的数量和时间跨度上限、退出余量，以及溢出后的不完整归档。Noetic 首次固定单核运行的两项锁存发布测试等待超时，取消测试进程亲和性后的重跑与最终验收通过。
- Noetic 以 1× 在逻辑 CPU 2、OpenMP 单线程下完整回放 `Retail_Street.bag`。节点接收 1,355 扫、27,447 条 IMU 和 1,355 张图像。前端得到 1,352 次 LIO、1,351 次 VIO，轨迹、前端日志、ROS 输出载荷和 516 个关键帧文件与基线一致。接受 2 次回环，位姿版本 2 的归档检查通过。
- 完整 Noetic 回放的 LiDAR、IMU、图像入口峰值分别为 1、27、1 条，合计采样峰值分别为 2、48、3 条。停机后入口全部取空，算法中还保留 24 条 IMU 和 2 帧缺少同步条件的图像。两种回放计数和入口诊断均记录到摘要。
- Humble 用同一数据的 ROS2 转录做两组 10 秒回放。两组都完整接收数据，轨迹与对应基线一致，得到 98 次 LIO 和 97 次 VIO。双 ROS 额外通过 5 秒纯 LiDAR 回放，分别完成 50 次更新。相机和 IMU 仍由观察端计数，节点只订阅 LiDAR。
- 启用 IMU 传播的 10 秒配对回放中，Noetic 的输出间隔 P95 从 135 ms 变为 110 ms，有效间隔样本从 202 个变为 163 个。Humble 在单核回放中的 P95 从 1.24 s 变为 1.16 s，有效间隔样本从 41 个变为 77 个。实际输出间隔随该轮可用的 IMU 和处理负载变化。

| 传感器 | 原版转换后系统锁等待 P95 | 入队锁等待 P95 | 入队后排队 P95 |
| --- | ---: | ---: | ---: |
| LiDAR | 20.9 ms | < 1 µs | 1.1 ms |
| IMU | < 1 µs | < 1 µs | 38.6 ms |
| 图像 | 109.7 ms | < 1 µs | 39.0 ms |

完整 Noetic 回放的 LIO 和 VIO 发布调用 P95 分别为 0.057 ms 和 0.175 ms。本轮保留系统所有者内的顺序发布。

配对摘要和构建日志保存在工作区的 `validation/slam-ingress-20261124/`。其中 `phase-2-3-noetic-comparison.json` 记录完整回放对比，`phase-2-3-extra-comparison.json` 记录 Humble、纯 LiDAR 和传播结果。
