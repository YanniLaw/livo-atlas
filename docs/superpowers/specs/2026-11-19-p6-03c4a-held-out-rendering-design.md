# P6-03c4a 留出视角画质基线

2026-11-19，设计稿。依赖 C3c2b 留存的封口地图和关键帧数据。实测预检查已经完成，
正式实现见[实施计划](../plans/2026-11-19-p6-03c4a-held-out-rendering.md)。

## 目标与选择

在固定前端观测、最终位姿和子地图分组下，测量当前增量训练模型在留出视角的画质。
对同一查询比较单块与相邻两块的渲染，为后续覆盖、选帧和增密实验提供配对基线。
P6-03b 已用两帧证明离线留出可行。C3 系列验证了多块坐标和在线发布，在线预览的查询来自
训练视角。最终资产只记录当前保留的训练帧，曾参与训练后被窗口淘汰的帧仍可能影响参数。
相关实测见 [P6-03b](../../p6-03b-validation.md)和 [C3c2b](../../p6-03c3c2b-validation.md)。

| 路线 | 能回答的问题与代价 |
| --- | --- |
| 检查既有在线地图的训练帧预览 | 快速检查显示和闭环绑定。窗口中不存在的 ID 无法单独证明留出 |
| 固定最终位姿并离线执行同一个增量模型 | 隔离训练数据和渲染变量，可复用保存数据。得到封口后的画质基线，时序仍是离线 |
| 回放期间排除留出帧 | 可测在线画质和输入积压。需要统一初次训练、组内修复和恢复的观察过滤 |

本阶段采用第二条路线。先固定样本和测量方法，第三条路线可在实时效果成为验收目标时另行实施。
只增加离线评估入口和必要测试。使用已有的观测导出、增量模型、联合渲染和指标计算。
用户此前要求在新阶段正式编码前通知以便切换模型。

## 输入与划分

- 输入为同一次存档的 `keyframes` 与带成功 Finalize 的 Gaussian 目录。复用地图、最新位姿、
  封口成员与资产检查。已归档状态用于验证来源和读取分组、位姿。训练从空模型开始。
- 用每组权威的主成员 ID 升序划分。固定留出第 2 帧。6 帧及以上再留出零基下标 `n // 2`。
  其余均按 ID 增量训练，包括后来会被活动窗口淘汰的帧。每组支持 3 到 32 个主成员，
  整个快照最多 512 帧。遇到缺失观测或不支持的组须指出失败的 ID。
- 任何模型初始化前固定全序列的 `split.json`。记录版本、封口成员、训练及留出 ID、
  `dataset.yml`、对应位姿/分组文件和所用 frame.yml、原图、点云哈希。用相对路径记录来源。
  检查训练与留出 ID、采集时间和原 PNG 哈希无交集。缺少有效训练深度时报告失败。
- 训练函数只接收计划中的训练观测。对每次 `train_candidate` 记录实际监督 ID，
  核对高斯来源与训练集合和当前保留成员。留出图像/深度仅供渲染评分。
  前端原先处理了连续图像，留出只针对 Gaussian 建图，位姿仍是 SLAM 估计结果。

本机预检查使用 `validation/P6-03c3c2b-20261119` 的 `review-full-on/keyframes` 和
`g-review-full-on`。最终位姿版本 2，共 172 帧、13 个封口组，固定划分为 147 训练和 25 留出。
用现有导出器逐组读取了全部 172 帧，每帧有 11,550 到 13,846 个有效稀疏深度像素。
跨集合的相同采集时间及相同原图哈希均为 0。预检查使用原始位姿导出观测，尚无训练或画质结果。
本机明细见 `validation/P6-03c4a-preflight-20261119/retail-street-preflight.json`。

## 坐标、模型及渲染

继续使用 `livo_atlas_prepare_3dgs_views` 原有接口。`MakeReconstructionView` 在 body
坐标系投影稀疏深度，保存的 RGB、K、掩码和相机 z 可以用于最终位姿。
Python 加载后通过原始相机和 body 位姿恢复外参，再绑定到已经校验的最终父坐标系。

```text
camera_from_body   = camera_from_odom @ odom_from_body
camera_from_parent = camera_from_body @ inverse(final_parent_from_body)
camera_from_submap = camera_from_parent @ final_parent_from_anchor_body
```

训练输入第三个变换的局部系使用该组首个主成员 body 系。查询给渲染器的相机位姿使用第二个变换，
对每块分别乘该块锚点的最终位姿。转换使用 float64，复用现有渲染器的 gsplat 像素中心转换。

按组依次创建 `OnlineGaussianModel` 并用现有 `train_candidate` / `decide(True)`。
保留既有每帧 20 步、窗口 10 帧、每帧最多 1000 个高斯。训练后释放 GPU 模型，
只保留本组及上一组独立 CPU 渲染参数。每张留出图使用同一相机和图像掩码，先渲染本组，
再渲染本组与前一逻辑组。首组只做单块。双块一起光栅化，共享遮挡排序。
第二帧与中间帧分别统计。这一划分按成员顺序，画质差异还需结合真实视角和覆盖解释。

## 报告与验收

结果包含划分清单、逐帧和汇总指标、参考/单块/双块 RGB、训练和每次渲染的耗时、
PyTorch allocator 峰值及进程 RSS。RGB L1/MSE 统计完整有效掩码内的像素，
包括低 alpha 区域。汇总 PSNR 由按有效像素数加权的 MSE 计算。覆盖率采用 `alpha >= 0.05`。
稀疏深度误差同时报告可用/覆盖样本数。没有深度计分样本时写 null。
比较汇总使用相同的 23 个可配对查询，独立列出首组的两个单块结果。

可复现要求为 147 次训练确认、25 个有效留出评分、23 次双块对照，所有实际训练和来源 ID
与清单匹配。输出写入新目录，逐组释放中间观测，输入哈希复查通过后最后写成功 `report.json`。
每次推理最多 2 块、20,000 高斯、1M 像素。单进程顺序运行并限制 BLAS/OMP 线程。
真实数据验收记录全部指标和代表图像，允许如实看到无收益或退化。后续可用同一划分测单个改动。

GaME 将输入视角与留出视角分别计分，用已知位姿隔离建图。这里借鉴这两点，使用本工程打包的
SLAM 最终估计位姿和项目自己的分组。 [GaME, CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/papers/Yugay_Gaussian_Mapping_for_Evolving_Scenes_CVPR_2026_paper.pdf)

固定划分也见原始 3DGS 的训练/测试数据加载。每组的具体留出位置来自本工程的测量目标。
[3DGS 官方数据加载器](https://github.com/graphdeco-inria/gaussian-splatting/blob/main/scene/dataset_readers.py)
