# P6-03c：在线 Gaussian 建图与位姿版本设计

2026-11-16，基于 `bbb2cdf`。本文是后续实施的设计，不代表在线 Gaussian mapper 已实现。
目标是在现有 LiDAR–IMU–视觉前端和 GTSAM 回环后端旁，增加可选、增量运行的 3DGS
建图，并为后续长期地图、闭环修正和 3DGS 研究留下清晰的数据边界。用户要求普通 C++ 核心
与 ROS 分离，ROS1 Noetic 和 ROS2 Humble 共用入口，只修改 livo-atlas，遵循 Google C++17
风格与函数间空行，避免 Pimpl 和提前构建通用插件框架。正式编码前先通知用户，以便切换模型。

2026-11-18 状态：C1、C2a、C2b 已完成，分别见
[C1 验证](../../p6-03c1-validation.md)、[C2a 验证](../../p6-03c2a-validation.md)和
[C2b 验证](../../p6-03c2b-validation.md)。下一步的
[C3a 最终收敛设计](2026-11-18-p6-03c3a-gaussian-finalization-design.md)已写出并完成
独立可实施性检查，尚未实施。下面的现状描述保留原设计时的语境。

## 当前事实与相关工作

已有 `OnlineSubmapUpdate` 提供拥有数据的关键帧、成员修订、位姿快照与位姿变化；
回调在 `LivoSystem` 所有者线程运行，必须不重入且不抛异常。当前只有一个在线回调，
`src/app/livo_main.cc` 已在此回调中分发给回环、轨迹和几何输出；新增消费者必须加入该
分发，不能覆盖其他消费者。回环后端在所有者线程 `Poll()`、`Finish()`，其关闭过程中
仍可能提交位姿；mapper 只能在后端完成后的合适顺序关闭。

`MakeReconstructionView` 接受关键帧和一致的 `PoseSnapshot`，返回独立的 BGR 图像、图像
掩码、稀疏相机 z 深度及其掩码。`KeyframeReadView` 目前只提供 raw pose、时间和有界
body 点云读取，不提供完整图像读取；本阶段直接使用通知中的拥有数据的关键帧，不假设它
能异步读取完整观测。重建时由调用方显式传入与数据集对应的 `CameraConfig`，不能从
`LivoSystem` 内部私有状态推断标定；当前数据集只接受 calibration ID 0，其他 ID 明确拒绝。
快照前沿可随新帧增长，同一位姿版本下既有帧位姿保持稳定；版本 0
的父系为 odom，正版本为 map。子地图局部系固定为第一个主成员的 body 系。

P6-03b 已在本机独立 Python 3.10、PyTorch 2.3.0+cu121、gsplat 1.5.3 上跑通 10,000
高斯的离线渲染和训练；留出图像有明显空洞，结果不证明在线吞吐。现有 Retail_Street 约
135 秒的 Noetic 完整回放曾产生 172 个关键帧，平均约 1.27 个/秒，实际间隔并不恒定；
此数据可测试短段并发和资源，不足以证明长距离或长期重访。实测数据、环境和限制见
[P6-03b 验证记录](../../p6-03b-validation.md)。

参考已有[调研](../../online-3dgs-submap-research.md)及本次核对：

- [Gaussian-LIC2 官方实现](https://github.com/APRIL-ZJU/Gaussian-LIC/blob/master/src/mapping.cpp)
  使用单独建图线程；它的具体输入、资源调度不能直接视为本工程验证结果。
- [LoopSplat 官方实现](https://github.com/GradientSpaces/LoopSplat/blob/main/src/entities/gaussian_slam.py)
  保存高斯子地图并处理整体修正；其 RGB-D 输入和闭环方式不同于本工程。
- [Splat-SLAM 官方 mapper](https://github.com/google-research/Splat-SLAM/blob/main/src/mapper.py)
  记录高斯的来源关键帧并对关联参数作位姿更新；多视图优化后的结果并不因此变成精确几何。
- [RMGS-SLAM 论文](https://arxiv.org/abs/2604.12942)提出异步高斯优化、voxel-PCA 几何先验
  和高斯配准闭环；这是一种研究选择，不在本阶段照搬。VIGS-SLAM
  的[官方运行说明](https://github.com/cvg/VIGS-SLAM)区分纯在线与结束后的额外优化，
  本工程的评估也应分别报告两者。

上述是作者的方法及源码观察，并非本机复现、跨项目性能对比或穷尽最新工作。

## 路线与阶段

| 方案 | 优点 | 代价与决定 |
| --- | --- | --- |
| 在节点内直接链接 LibTorch/CUDA | 少一次进程间传输 | 节点、ROS 系统库与 GPU 运行时共享 ABI 和故障；需要重新处理 Noetic 的依赖组合，暂不采用 |
| 独立 Python/gsplat 进程，加普通 C++ 有界桥接 | 复用已验证后端，GPU 失败与 ROS/前端隔开，ROS1/2 共用桥接 | 需要明确传输、生命周期和版本提交；作为首条实现路线 |
| 仅写盘，结束回放后再训练 | 实现简单 | 不能验证输入运行期间的训练与积压，保留为离线基线，不作为本阶段交付 |

分阶段实施，避免把试验结果误称为完整地图：

1. **P6-03c1：单活动子地图在线试验。** 外部启动一个 GPU worker，C++ 桥接从现有回调
   接收关键帧；实时准备观测、增量训练、提交带版本的渲染预览。只维护一个活动子地图的
   有界工作集，版本变化时保守清空并用最新观测重新初始化；支持数据隔离和故障退化。
2. **P6-03c2：多子地图与闭环一致性。** 设计 CPU/磁盘与 GPU 活动集，持久化/恢复、
   整体刚性更新、组内变化的来源关联修正或重建、过期任务和优化器状态。必须另写详细
   格式和验收，不把 c1 的临时传输格式当长期资产。
3. **之后：画质、动态物体和研究。** 在受控基线上研究体素几何先验、覆盖与共视选帧、
   densification、可见性及多视图优化；若研究渲染残差参与前端或闭环，再单独评估量测相关性。

c1 不保留历史高斯子地图，不提供全局高斯地图、自动恢复、Gaussian 回环、ROS 高斯话题或
向前端反馈；这些是明确的阶段边界，不影响已有观测、几何地图和 GTSAM 后端。

## P6-03c1 数据流与所有权

```text
LivoSystem 所有者线程（单一回调）
  ├─ 既有 LoopBackend / 轨迹 / 几何消费者
  └─ OnlineGaussianMapper::Observe：记录拥有数据的快照，返回
         ↓ 单个待处理关键帧 + 一个在途任务，允许合并观测
     C++ 背景线程：MakeReconstructionView、有限长度 IPC
         ↓ 同机 Unix domain socket，独立且用户显式启动的 GPU 进程
     Python/gsplat：初始化、固定步数训练、生成候选预览
         ↓ 所有者线程核对版本及接纳确认
     带子地图、位姿版本和覆盖关键帧的预览与统计
```

仅发送**主成员**，不把支持关键帧重复加入相邻子地图。`Observe` 必须 `noexcept`，不做
GPU、网络、文件读写、去畸变或等待；持有 `shared_ptr<const Keyframe>` 和
`shared_ptr<const PoseSnapshot>`，不保存通知对象的引用，不通过别名修改图像或点云。
异常在 mapper 内记录为失败，不传播到 `LivoSystem` 或其他消费者。主线程的 `Poll()`
检查背景结果，不做阻塞 I/O；同一回调先后分发，各消费者原有行为不变。

`Observe` 和 `Poll` 的可变状态仅由系统所有者线程持有；背景线程只访问任务与结果邮箱。
邮箱交接使用非阻塞尝试，交接失败时所有者线程保留最新待办并在下一次 `Poll` 重试，
不能因为锁竞争丢掉最新位姿。小量元数据分配失败也必须被捕获并使 mapper 进入失败状态。

排队规则由实现者按此约束落实：至多一个任务在途、一个最新待处理关键帧，后者可被更近的
主关键帧替换，替换次数计数；另保留一个最近已选关键帧用于位姿更新后的重新初始化，三个
槽位可引用同一对象。没有图像、无有效深度或资源超限的帧被计数并跳过。不是每个关键帧都
保证参与训练；原有关键帧持久化和回环通知不受跳帧影响。子地图成员修订、最新位姿与
观测丢弃分开处理：位姿状态以最新完整状态覆盖旧状态，不放入可丢弃观测队列。

保留的快照和任务必须有上限；快照内部轨迹随前沿增长，本阶段限制快照前沿最多 512 帧，
达到上限后停止 mapper 并报告 `resource_limited`，前端和其他消费者继续。此限制不保证
`LivoSystem` 或其他模块的总内存有界。不得在回调中复制整段图像/点云，也不得假定
`shared_ptr<const Keyframe>` 能阻止 `cv::Mat` 的别名修改。

## 局部坐标与版本提交

记 `T_A_B` 为 B 坐标到 A 坐标。针对某一子地图 S，以快照中其锚点姿态定义
`T_parent_S`；从重建视图得到 `T_camera_parent`，训练输入为
`T_camera_S = T_camera_parent * T_parent_S`。Python 反投影得到的高斯均值位于 S，
输出预览携带 `parent_frame`、`T_parent_S`、关键帧 ID、成员修订、位姿版本、覆盖前沿与
本会话 ID。不得再次施加 LiDAR 外参。OpenCV 主点转 gsplat 时仅加 0.5 一次，深度仍为
相机 z 米值；零深度由掩码排除，前端逆曝光估计不直接修正颜色。

生产者每次启动生成新的会话随机 ID；协议中的帧 ID、子地图 ID、模型修订和位姿版本只在
此会话内解释。每个任务另有递增 ID 和本地代数 `generation`。`generation` 在活动
子地图改变或任何新的位姿版本到达时递增，同版本只增加帧前沿时不递增。
这里的当前子地图指最后一个接收主关键帧的子地图：当其达到容量或 `SealInput` 使之
封存后，仍可完成已接收任务和处理位姿更新；出现下一个子地图时才切换。一次通知可能
同时带有旧子地图封存、新子地图创建，或同一子地图追加后立即封存，均按实际主成员归属处理。

- 相同活动子地图、位姿版本和 generation 下，成员只允许按既有契约追加或封存。即使更
  新关键帧已经到达，较早任务仍可提交，但必须报告它实际使用的成员修订和关键帧集合，
  不能冒充已经处理更晚的帧。新子地图出现后旧子地图的候选不得提交。
- 任何新位姿版本到达时立即使当前可用预览失效；c1 保守丢弃旧模型及优化器，再使用该
  子地图中最近已选关键帧和最新完整位姿重新初始化。该策略也用于整体刚性修正，代价是
  丢失旧训练进度；不声称已对历史高斯做增量闭环修正。若没有可用的最新观测则保持非就绪。
- 旧候选不能只被拒绝显示：Python 训练是原地修改的，拒绝后必须清空整个受影响模型及
  Adam 状态，不能让被拒绝梯度留在下一任务里。`Poll()` 必须在确认结果时再次对照当前
  会话、任务、子地图、位姿版本和 generation；中间版本可被合并，但最新状态必须最终
  到达 worker，不能依赖被丢弃的增量 `pose_changes` 才能恢复。
- 候选产生后，worker 等待接纳/丢弃；接纳后回确认，主线程收到确认时再次检查版本才
  对外提供预览。若确认前又发生位姿更新，结果仍丢弃并清空模型；连接中断时不复用
  该进程中的旧模型。已写出的历史预览带完整版本标签，不把它当作当前地图。

位姿控制有独立的 `RESET` / `RESET_OK`，不是依赖后续关键帧顺带执行的任务：即使 worker
空闲且之后没有新观测，也要将最新 generation、子地图 ID 和位姿版本发给 worker，并等待
确认其模型、观测窗口和 Adam 状态已清空。生成新的代数后，在最新 `RESET_OK` 与所有者
线程的当前代数一致之前，不得发送新的训练任务。若 `RESET` 在途时又有更新，则允许跳过
中间版本，待前一确认到达后再次发送最新绝对状态；不因缺失增量消息而恢复旧模型。
若 worker 正在训练，等待其候选并拒绝，或在任务超时后将 mapper 标为失败；不能宣称卡住
的 GPU 调用能即时接收 reset。若接纳已发出但确认前发生更新，收到旧确认后发 `RESET`，
不发布旧预览。活跃连接最终同步最新状态的保证以 worker 正常响应、所有者继续 `Poll`
为前提；连接失败时明确失败，不承诺后台自动恢复。
若尚无子地图，控制消息省略子地图 ID；本机 OpenCV 4.2 JSON 解析器不接受 JSON null。

c2 若优化刚性更新，必须先证明相对于同一锚点所有已用观测的局部位姿不变，再只更改
`T_parent_S`；组内变化时按来源关联修正并重训，或从观测重建。均值、各向异性旋转/尺度、
方向相关外观及优化器状态要一起处理。c1 不假定把全局修正和局部修正各应用一次就是正确的。

## 进程边界与资源预算

Linux 上使用一个由用户显式启动的 Python GPU 进程与一个本机 Unix domain stream socket；
同一系统入口可由 Noetic 或 Humble 使用。socket 在实验目录内创建，工作目录权限为 0700，
不开放 TCP；只允许一个会话，路径已存在、过长或握手不匹配时失败。该传输属于可选模块，
不是公共跨平台协议；其他平台需另选适配，默认 C++ 核心不依赖 Unix socket、Python、
CUDA、PyTorch 或 gsplat。本阶段不自动启动、杀死或重启用户进程。

内部协议版本 1：每个消息依次为 4 字节小端 JSON 头长度、8 字节小端 body 长度、UTF-8 JSON
头与 body。头不超过 64 KiB，body 不超过 16 MiB；先检查长度，再分配与读完整消息。
非 ASCII 文本直接用 UTF-8，协议不使用 OpenCV 4.2 不支持的 JSON `\u` 转义。
消息种类限定为握手、观测任务、候选结果、接纳/丢弃、确认、重置/重置确认、错误及结束；会话 ID、任务 ID 和
generation 每次校验。观测 body 依次为逐行 BGR `uint8[H,W,3]`、图像掩码和深度掩码
`uint8[H,W]`、小端 IEEE-754 深度 `float32[H,W]`；头记录宽高、焦距、OpenCV 主点、
行优先 `T_camera_S`、时间、身份与版本。掩码只允许 0/1，深度掩码是图像掩码子集，
深度有效时有限且为正、其余为 0。候选预览为 RGB `uint8[H,W,3]`，携带宽高并关联同样
的身份，由接收端核对它与对应任务一致。
半包、EOF、非有限矩阵、越界长度、错误顺序或错误身份必须显式失败，不把部分数据当结果。
握手后发现 GPU 或预编译扩展不可用时，worker 应返回有界错误类型并退出；在无法建立协议
时允许记录 EOF/启动错误，但不得将其报告为成功。

socket 由后台线程使用非阻塞读写和 `steady_clock` 超时，不能在所有者线程等待连接、网络
缓冲或 GPU。初始默认：连接/握手 10 秒、单次传输 5 秒、单任务 30 秒、停止等待 3 秒；
超时或 worker 退出时关闭 socket、取消任务并将 mapper 标为失败，前端继续。正常 `Finish`
在回环后端完成后尽力处理最终位姿和最近观测，最多按上述停止等待期限排空；未排空时计数
并报告未完成，不能沿用之前版本伪装成最终结果。被卡住的系统调用或 GPU 驱动不提供硬实时
退出保证，未确认的结果一律无效。没有自动重连，重新启动 worker 和 mapper 后会生成新
会话，不能沿用旧结果。

初始试验上限：单视图最多 1,000,000 像素、100,000 云点；worker 保留最近 10 个已选主
关键帧，每帧按行优先均匀采样最多 1,000 个有效深度，高斯总数最多 10,000。新增第 11 帧
时移除最旧视图及其来源高斯；因参数形状变化重建 Adam，其他仍保留的高斯参数不清空，
所有优化器动量重置。每次新观测最多 20 个单视图更新：10 步当前帧、10 步按 ID 升序
循环取其余保留帧；没有其他帧时仍用当前帧。初始尺度、透明度、颜色参数化和损失沿用
P6-03b，颜色 RGB、RGB L1 加 `0.05 * depth L1`；不进行 densification 或透明度剪枝。

只使用一个 GPU，启动时可用显存至少 4 GiB，PyTorch 分配比例 40%；保留预编译扩展
检查，失败不得隐式 JIT。最多 1 个 in-flight 消息及 1 个待处理观测，限制 body、视图、
高斯与帧前沿，不声称已约束 OpenCV/Python/驱动或其他进程的全部内存。连接、步数、内存
与保留视图配置须在启动前验证；默认关闭，运行时启用需有关键帧和 online submaps。
这些值是本机试验起点，不是跨硬件性能保证。

## 可观察性与验收

必须分别记录 `observed`、`submitted`、`coalesced`、无图像/无深度/超限跳过、`completed`、
`accepted`、`stale`、`reset`、失败、当前/峰值 pending 与 in-flight、当前 pose version、
submap ID、generation、实际覆盖关键帧、训练步数、处理延迟和采样 GPU/进程内存。工作
生成的预览要带时间和身份，不把旧文件称为当前结果；前端帧延迟另计，不混同 GPU kernel
耗时。运行时由用户指定此前不存在的输出目录，后台滚动保留最近 8 份
`preview-<job>.png` 与同名 JSON 元数据；先完成图片，最后以原子重命名发布元数据，
只删除该会话在自有目录内创建的最旧完整预览。已有 8 份时，在发布下一份前先删除最旧
的一份；删除失败则停止预览写入并报告失败，不能超出上限。写入期间最多另有一份临时预览。
读取者若恰逢旧文件被删除，应重读索引，而不是把缺文件当有效图像。

当前就绪状态由所有者线程在内存中校验：子地图或位姿更新后立即不可用，新确认经过再次
校验后才可用。后台另外原子更新一个 `status.json`，标明会话、状态序号、写出时间、
子地图、位姿版本、generation、就绪标志及最近预览文件名；在后台、磁盘正常且所有者
继续轮询的前提下，慢 I/O 合并后的状态最终追上最新代数。这个文件只是异步状态采样，
可能短暂落后或在进程异常退出后过期，不保证与
前端同步；查看者必须核对时间和版本，不能拿它证明实时一致性。已生成的预览是当时接纳
的历史结果，位姿之后变化不会让它自动变成新版本。不得覆盖用户已有输出目录，输出不能
放入源关键帧数据集。由于当前无稳定高斯导出格式，c1 只输出有限数量的带元数据预览与指标。

1. 普通 C++ 和假 worker 覆盖单回调共存、追加/封存、队列覆盖、线程归属、坏消息、半包、
   超时、无响应及关闭；验证观察/轮询不等待 GPU 和 socket，不新增 ROS/GPU 依赖到核心。
   另检查滚动预览保留最新 8 个、慢磁盘状态最终追上最新代数，内部接口不返回旧预览。
2. 确定性竞争测试覆盖任务训练中跨两次位姿更新、子地图切换、同版本前沿增长、确认前
   再次更新；不仅检查旧预览被拒绝，还检查原地污染模型和 Adam 状态被清空。模拟刚性与
   非刚性改变，c1 均按版本重建，不把该测试称为真实闭环精度。
3. Python/GPU 合成测试覆盖坐标、颜色、深度掩码、预编译扩展、固定步数、上限与淘汰；
   实际缺 GPU、进程崩溃和协议错误可观测，不回退成虚假成功。
4. Noetic 先短段后完整 1× Retail_Street，进行关闭/开启的同平台成对回放；输入计数、
   前端数组、原始关键帧资产和已有回环/输出行为必须分别核对。观测真实在线训练在输入
   未结束前发生，统计跳帧、前端延迟、端到端延迟、CPU RSS 和 GPU 峰值；非零训练不等于
   跟上输入。ROS2 Humble 至少验证同一主入口、参数和假 worker 交接；没有可用 GPU 的
   容器不宣称实际 GPU 通过。
5. 保留输入前后哈希、源码提交、软件版本、资源监测和全部日志。真实回环是否出现以记录
   为准；已知人工修正和约 135 秒 bag 不能证明真实长距离、绝对精度或长期地图一致性。
   单视图训练预览不作为独立新视角质量指标，停止输入后的额外优化与在线结果分开。

原详细实现计划只覆盖 c1；c1 实测后的 C2/C2a 方案见本文开头的新文档链接，编码仍单独通知。

## 设计检查

独立只读 builder check 指出：空闲 worker 或候选已接纳时，不能依赖下一帧才清理旧模型；
达到子地图容量时可能在同一通知内追加并封存；只保存最早预览会让后续结果不可见。本文已
分别补充独立 `RESET` / 确认、封存后保留当前子地图，以及有界滚动预览和异步状态采样。
检查者复核后没有提出其他影响制定计划的重要问题；这不是实现或运行验收。
