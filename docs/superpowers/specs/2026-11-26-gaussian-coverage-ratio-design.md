# 高斯空洞种子预留比例

用户已认可参数化固定 50% 比例，并在相同预算下比较 0% / 25% / 50%。沿用本会话直接实施、
本机验证与本地提交的授权，在当前 framework_completion 分支完成，不修改 vikit。

## 选择与语义

沿用现有 train / OnlineGaussianModel 和共享 worker YAML，不引入新采样器或编译宏。
新增 `gaussian.worker.coverage_uncovered_ratio: 0.5`，接受有限数值 [0,1]，拒绝 bool、字符串、NaN/Inf。
该值是每观测高斯定额中**优先**留给未覆盖深度像素的最大比例，不保证最终未覆盖种子只占此比例。
预留数为 min(floor(limit * ratio), uncovered)，其余按原始顺序均匀补齐且不重复。
没有历史模型、全部候选都未覆盖或候选数未超定额时保留原始 uniform 行为。
比例为 0 时跳过覆盖预渲染并逐数组使用原始 uniform 初始化；比例为 1 时允许补齐集合为空。
默认 seed_policy 仍为 uniform，coverage 默认比例 0.5 与现有行为一致。

## 配置、证据与比较

WorkerOptions 向初始化和覆盖预渲染传递同一比例，完整配置继续从 config/gaussian.yaml 读取。
训练记录的 reserved_uncovered 必须与该比例一致；旧记录缺少新字段时按旧默认 0.5 校验。
新的固定预算输出归档原始 config.yaml，其字节 SHA 必须匹配报告，优化器设置也须匹配解析结果。
比较工具默认继续要求相同配置；显式 --allow-coverage-ratio-change 时，仅允许该 YAML 键和
对应的 WorkerOptions 字段不同，其他配置、学习率、输入、位姿、选块、调度、高斯数量仍逐项核对。
比例试验以 coverage/0 为基线（其初始化和预渲染路径已验证等价 uniform），候选为 coverage/0.25 或0.5。
这样只变化一个数值；默认 uniform-vs-coverage 对照入口仍可用。

## 验证与实验

- 先验证比例边界、准确采样序列、空补齐集合，以及真实 CUDA 下零比例与 uniform 的一致初始化和训练。
- 验证 ratio 配置差异在默认比较中被拒绝，显式模式允许比例差异但拒绝其他 YAML/优化器变化、
  篡改配置和不一致的种子预留记录；历史比较仍按默认0.5工作。
- 使用已有 172 帧参考快照及冻结划分（150 train /22 heldout /21 query），同一空间邻居。
  三个比例各重复两次（种子0/1），GPU顺序运行；每次150次训练/3000步，窗口10、每观测上限1000。
- 同步比较单块/联合 RGB/SSIM、覆盖新增与丢失、六次共同像素深度、训练时间与分配器显存。
  记录参数量和预渲染次数，区分采样等价与 CUDA 浮点归约不保证逐位重复。
- 原始 bag 不复制；约2.4GiB评分产物，至少1GiB磁盘保留，保持原始证据不变。
- 现有数据作为开发验证；本轮不按单场景选择新的默认策略。最终说明是否值得保留中间比例。
