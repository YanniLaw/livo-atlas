# 在线留出视角画质评估：设计草案

状态：第一阶段训练划分和来源隔离已实现，见[验证与复现](../../gaussian-holdout-isolation.md)。
第二阶段已实现[独立查询、固定指标与最终快照只读评分](../../gaussian-heldout-scoring.md)。
在线留出请求协议、封口触发与公平调度仍待接入；现有结果是最终快照成绩。
目标是在当前单 GPU worker 的在线训练过程中，对从未进入高斯训练的相机图像评分，
同时保留实时前端、异步后端、现有预览和正常退出语义。

## 现有能力与首版选择

已有 [C4a](../../p6-03c4a-validation.md) / [C4b](../../p6-03c4b-validation.md) 在最终位姿上
从空模型训练，再评估固定留出视角。可复用观测准备、来源核对、渲染和指标代码。
`evaluate_gaussian_submaps.py::split_primary_ids()` 会根据最终组大小选中间帧，不能直接
作为在线训练开始前的划分。当前 `SelectGaussianRender()` 则选择已确认训练窗口中的
相机；现有 READY 接收记录不构成留出视角的画质证明。

| 方式 | 用途与代价 |
| --- | --- |
| 子地图封口后的在线快照评分，另做最终状态评分（推荐） | 与现有持久资产边界衔接，任务量有界，可比较在线模型与最终模型 |
| 每个留出帧到达时立即评分 | 可研究当前时刻的预测能力，但需要额外定义在途训练、快照冻结和调度时限；留待后续 |
| 只在最终位姿上离线重训评分 | 保留为已有对照，不能代表实际在线模型的质量 |

首版采用第一项：封口事件产生待评分任务，实际派发时捕获明确的模型、位姿和来源快照。
这是在线建图期间对历史留出视角的回看，不声称使用了该图像到达瞬间的地图。记录封口
时间、派发时间与实际 `as_of` 前沿；等待期间发生的回环不能被隐藏。

## 训练前冻结划分

1. 首轮使用现有 Retail_Street 前端数据集准备不可变 manifest，在线 Gaussian 从空状态
   启动。每个 ROS/依赖环境有自己的前端基准；不能把跨 ROS 相同 ID 视为同一图像。
2. 建议初始规则为关键帧 `id % 8 == 1` 留出，其余用于训练。规则只用于生成 manifest，
   运行时以完整 manifest 为准。每组最多选两个留出查询，按 ID 排序，在准备阶段确定；
   其余留出帧仍禁止训练，并单列为未选评分帧。
   短段先冻结对应前缀范围与末组成员，范围外观测/查询单列为 not_in_scope，不能在训练后
   才改写划分来适配结果。
3. manifest 绑定输入数据、前端配置/依赖、相机标定及逐帧 ID、图像时间戳、RGB/点云摘要、
   分组与角色。规范化后生成 `split_id`；相同 ID、时间戳或 RGB 跨训练/留出两侧重复时
   拒绝准备，复用已有 `check_split_identity()` 的规则。
4. 在线观测必须与 manifest 匹配。未列出的帧、时间戳/图像/标定不符时明确失败，不重新
   分类、不静默跳过后继续宣布评估通过。更换前端环境时重新准备划分，再从空模型运行。

留出帧可以作为子地图坐标锚点，坐标定义不要求其 RGB 参与训练。若某组没有可训练观测，
明确记录无模型，不能把留出帧补作训练样本。原 SLAM 前端继续使用完整传感器流估计位姿；
这里隔离的是高斯训练数据，不宣称留出图像未参与视觉里程计，也不将 SLAM 位姿当作真值。
前端也保留完整 LiDAR 流；该实验不宣称留出时段的三维几何从未被系统观测。

## 防止数据泄漏

- 在 Gaussian 任务准备及 worker 接纳两端核对角色，覆盖普通 view、pending 合并、窗口
  选择、seed/增密、回环 rebuild 和恢复路径；不能只在 ROS 订阅层或新帧入口过滤。
- primary membership 与位姿前沿保留完整 SLAM 语义，实际训练观测是其中的 train 子集。
  prepare/rebuild 只读取该子集，重新绑定几何不能偷偷补入留出 RGB 或深度。
- 每次训练记录实际用于损失与播种的观测 ID，保存完整训练 lineage。最终十帧窗口和
  Gaussian `origin_ids` 都不足以证明早期被移出的帧没有参与优化。
- 每份确认/持久状态绑定 `split_id` 与 lineage 摘要。旧资产没有该证明、划分不同或历史
  不可核对时拒绝恢复。不能对现有全帧训练模型事后挑几张图并称作无泄漏留出评估。
  资产按现有严格 schema 做显式版本迁移，不向旧版本随意加入未知字段。
- 渲染评分不得修改模型参数、优化器或训练 RNG。单独记录评分开销，避免把推理时间
  计入训练调用耗时。

## 快照、查询与单 worker 调度

留出相机通常不属于训练窗口，不能放宽现有预览查询校验来兼容。实现时使用独立的
evaluation 请求/结果语义，通过 worker capability 协商；复用现有双块推理原语，保留
READY 的原有来源与失效规则，不增加第二个在线模型或并行 GPU worker。
新能力只在显式协商后启用，关闭功能时保留现有握手与严格校验。

待评分任务只持有查询 ID 和计划信息。派发前经过既有 decision、持久化和 map 确认边界，
再捕获 source job/content/asset、map_sequence、位姿内容摘要、标定和完整相机位姿。
在途期间沿用单 mailbox 的串行保护；不在等待期间持有大图像或无限堆积模型副本。
待查询列表来自有界 manifest，由游标调度，实际 pending/in-flight 各最多一个。

每个查询用同一相机与同一份来源快照评估单块、存在时的联合块。选择策略沿用当前
temporal/spatial 配置并写入报告。快照结果可以在最新地图前进后作为历史测量保存，
但必须证明捕获的来源未变；不能用预览的“是否最新”条件丢掉慢样本而造成选择偏差。

评分与预览共享有界推理机会，保留内容更新/历史修复的优先级与公平性。任务无法在在线
阶段完成时单列原因，不把后续最终评分补算成在线成绩。owner 只登记计划与元数据，
图像读取、GPU 推理、指标计算和写盘均不进入前端 owner 的处理循环。

正常停止时取消未派发在线评分，受控处理在途任务后继续既有 Finalize/停止流程，不能
阻塞 STOPPED。最终资产封口并停止在线 worker 后，可顺序启动只读评分工具，以最终
位姿重评同一查询；只读取这些在线模型资产，不重新训练模型。它不向已结束的 ROS
预览通道发布 READY。

## 指标与数值口径

| 指标 | 固定定义 |
| --- | --- |
| RGB PSNR | 同尺寸、同标定的归一化 RGB 编码值域 `[0,1]`；在参考有效图像掩码上累计 MSE，再转换为 dB，沿用现有实现 |
| SSIM | 首版建议单尺度 RGB 三通道均值，11×11、σ=1.5、K1=0.01/K2=0.03、data_range=1；只统计参考有效掩码内完整窗口，不自动缩放图像 |
| 图像覆盖率 | 沿用 `alpha >= 0.05`，分母为全部参考有效图像像素 |
| 深度 L1 / RMSE | 相机光轴 z 深度、单位米；在有效 LiDAR 参考深度和已覆盖像素交集评分，同时报告全部参考深度数、实际使用数与深度覆盖率 |

SSIM 的定义参考 [作者页面及论文](https://ece.uwaterloo.ca/~z70wang/research/ssim/)；上述
RGB、掩码、窗口与缩放约定是本方案拟固定的实验口径，实现时需用独立参考核对。

RGB 主指标不能只选已覆盖区域，否则空洞会消失在分母中。深度没有参考时记为 null
并写原因；不足11×11或没有有效完整窗口时 SSIM 为 null。完美 RGB 的 PSNR 延续
`rgb_perfect=true`、数值 null 的有限 JSON 表达，不写 Infinity/NaN。保留逐查询误差和
有效计数；汇总从像素加权 MSE、深度误差累积量与 SSIM 有效窗口计算，不直接平均 dB。
深度来自 LiDAR 投影，称为参考一致性，不称绝对几何真值。

## 配置、产物与资源

配置统一进入 `config/gaussian.yaml`，当前参数如下；每组查询上限在冻结划分时确定：

```yaml
gaussian:
  evaluation:
    enabled: false
    split_file: ""
    max_output_mib: 256
    min_free_disk_mib: 1024
```

节点读取 `enabled` 和 `split_file`，最终评分工具也读取磁盘预算；查询上限由 manifest 固定。
启用在线隔离时要求持久化、在线子地图和有效
划分；划分中的查询数不能超出安全上限，运行中不任意挑“容易”的查询。

输出包含 split/source/software 摘要、逐次训练 lineage、逐查询相机与 as_of 来源、
RGB/SSIM/深度/覆盖率及有效计数、调度/耗时/显存、未完成和跳过原因。在线与最终阶段
分开。为复算浮点指标，保存有界的参考/浮点渲染 RGB、alpha 和深度样本（可无损压缩）；
PNG 只作为浏览副本，不能用量化后的 PNG 承诺逐位复算浮点 MSE。精确重渲染所需的模型资产是否
归档另行声明，不能只留下哈希却声称仍可重新渲染已剪除资产。

继承双块、20,000 Gaussian、1M 像素及现有 worker 显存预算。开始前估计模型资产、
关键帧及评估产物的磁盘量，并保留配置的空闲余量。预算不足不能静默删查询后验收成功。
先做短段单策略；完整双策略顺序运行，第一轮校验后可无损归档资产并精简本轮原始载荷。
当前机器剩余空间有限，本轮不生成新的完整 bag 或质量数据集。

## 验收与实施顺序

1. **划分和 lineage。** 先做纯数据测试：普通 view、窗口、rebuild、restore 均拒绝留出
   数据且不改变参数；未知/污染旧状态、重复图像、相机/观测变化均拒绝。正常前端轨迹
   与同环境参考一致，关闭 evaluation 的现有行为保持原样。
2. **查询与指标。** 测试独立留出相机、相机变换、过期但可核对的历史快照、单/双块来源；
   同图 SSIM=1、改变图像确实降分、空覆盖仍计 RGB 误差、零深度/掩码和小图像不伪造分数。
   验证推理前后参数/优化器/RNG不变，报告可从保存样本复核。
3. **在线接入。** 受控 worker 验证公平性、资源上限、来源变更、请求取消与超时。新增
   功能开启时，现有双 ROS 暂停 `/clock` 和 STOPPED 进程测试仍通过。
4. **真实基线。** 先用 Noetic 短段确认全过程与无泄漏证明，再做 Retail_Street 完整单策略
   在线/最终评分，之后接 Humble。`uniform`/`coverage` 只比较划分、查询、训练输入、
   位姿内容、预算匹配的样本，未配对项与原因单列，不用不同样本的均值声称策略收益。

每个预先选定查询必须有成功、明确跳过或失败终态，不能只汇报成功子集。首轮目标是
建立可复核基线，不预设未经测量的 PSNR/SSIM 提升门槛，不从一次 Retail_Street 推断
跨场景泛化、长距离定位精度或即时预测能力。第一阶段实施见
[执行计划](../plans/2026-11-26-gaussian-holdout-isolation.md)。
第二阶段见[查询与评分计划](../plans/2026-11-26-gaussian-heldout-scoring.md)。
