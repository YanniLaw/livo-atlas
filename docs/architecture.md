# LIVO-Atlas 目标架构

状态：初版设计，作为渐进重构的实施依据；本文描述的新增模块尚未实现。

实施入口见 [文档索引](README.md)，未定接口与门限见 [决策和契约](decisions-and-contracts.md)。每个细分任务由用户本地验收后才算通过，具体执行 [任务验收流程](acceptance-workflow.md)。

## 1. 目标与范围

以 FAST-LIVO2 为融合前端，逐步实现回环、全局地图、地图加载与重定位，并提供一致的 3DGS 数据。第一轮重构保留现有估计算法、观测顺序和默认运行行为。

第一版采用局部滤波前端与全局位姿图后端。紧耦合全局优化、多会话融合、在线高斯地图属于后续扩展。

编码遵循 [编码与设计规范](coding-standard.md)。本图和模块表表达职责边界，不要求每个职责独立建类、线程或库。以当前任务的最小清晰实现为准，不提前实现后续阶段的通用框架。

## 2. 模块与依赖

```text
ROS / 离线应用
       ↓
SlamSystem（生命周期与调度）
       ├── SensorSynchronizer → FusionFrontend
       ├── KeyframeManager → MapStore
       ├── GlobalBackend → 优化结果
       └── 结果分发 → ROS 输出 / SessionWriter

MapStore → MapSnapshot → 地图重建 / DatasetExporter
```

| 模块 | 负责 | 边界 |
|---|---|---|
| ROS 适配 | 订阅、消息转换、发布、TF、服务 | ROS 类型在此转换，不向新公共接口传播 |
| SensorSynchronizer | 缓冲、时间校正、扫描切分、生成处理事件 | 保留 LIO/VIO 顺序，不修改滤波状态 |
| FusionFrontend | IMU 传播、去畸变、LIO/VIO 更新、局部匹配地图 | 唯一拥有可写滤波状态；输出不可变结果 |
| KeyframeManager | SLAM 关键帧与重建图像选择 | 不修改前端估计 |
| MapStore | 观测、关键帧、标定、位姿版本与索引 | 区分不变观测和可更新估计 |
| GlobalBackend | 候选检索、回环验证、位姿图优化 | 消费关键帧快照，输出优化结果 |
| SessionWriter | 异步保存数据与元数据 | 有界队列、写入状态与失败处理 |
| DatasetExporter | COLMAP、点云、深度及元数据导出 | 消费固定版本快照，可离线运行 |
| SlamSystem | 配置模块、处理事件、启动与关闭 | 不实现观测雅可比、配准或文件格式 |

核心可继续使用 Eigen、OpenCV、PCL。取消 ROS 依赖采用渐进方式：先隔离 ROS 发布和参数加载，再转换同步器及 IMU 输入。不得用“无 ROS”目标驱动一次性重写算法。

## 3. 坐标与时间契约

- `T_A_B` 将 B 系点变换到 A 系；长度单位米，角度单位弧度。
- `odom` 为前端连续局部坐标，`map` 为后端全局坐标。
- 前端状态对应 IMU，输出 `T_odom_imu`；传感器外参明确为 `T_imu_lidar`、`T_imu_camera`。
- 现有外参配置通过适配函数转换，不能仅根据旧变量名推断方向。
- `T_map_camera = T_map_imu * T_imu_camera`；COLMAP 输出其逆变换。
- 光学坐标轴及文件四元数顺序必须在序列化接口中明确；内部尽量使用旋转类型。
- 新持久化时间采用整数纳秒；原算法内部可通过适配保留秒单位。
- 区分原始消息时间、校正后观测时间、扫描起止时间和去畸变参考时间。
- 时间偏移只应用一次，记录使用的标定版本；状态和发布消息使用实际状态时刻。
- 时间回退触发显式重置或新会话策略，不能把不同时间段混入同一轨迹。

## 4. 状态与数据所有权

FusionFrontend 拥有滤波状态、传播状态、IMU 处理器、激光局部地图与视觉局部地图。LIO 和 VIO 在其内部按顺序更新同一状态。旧指针接口可暂时存在于该封装内部，对外不暴露可写状态。

| 数据 | 生命周期与访问 |
|---|---|
| SensorEvent | 同步器生成，单次处理；明确事件类型和参考时刻 |
| FrontendOutput | 一次处理周期的结果，包含融合完成标记与质量信息 |
| ImageObservation | 不变图像、时间、标定 ID；不引用会被前端修改的缓冲区 |
| CloudObservation | 不变局部点云、参考坐标、时间区间、关联状态 |
| Keyframe | ID、观测关联、前端位姿、子地图归属 |
| PoseEstimate | 按版本保存优化位姿；与原始前端位姿分离 |
| MapSnapshot | 固定 ID 集合、标定和位姿版本，用于地图重建和导出 |

默认值类型与 `unique_ptr`；跨消费者共享大块不变观测时才使用 `shared_ptr<const T>`。`cv::Mat` 浅拷贝不代表不可变快照，发布前必须确认底层存储不会继续被写入。

关键帧与重建图像采用独立采样策略。额外图像保留直接状态关联或相对锚定帧位姿；后端据此更新，且记录这种更新的近似性质。

## 5. 前端结果出口

保留现有 LIVO 模式先 LIO 后 VIO 的执行语义。同步器可以产生不同处理事件，关键帧管理只接收明确结束的融合周期。

- LIVO：VIO 完成后输出本轮结果；跳过或失败时输出带原因的降级结果。
- LIO：激光更新完成后输出。
- 初始化未完成：发布状态信息，避免生成看似有效的关键帧。
- 内部中间状态可以用于诊断，但不得误作为同一时间戳的第二个关键帧。

重构中保留必要的兼容输出，逐项记录旧话题和新输出的时间、坐标与发布频率差异。

## 6. 后端与地图修正

第一版后端维护 SE(3) 关键帧位姿图。前端在 odom 中持续运行，后端不直接改写滤波状态或局部匹配地图。

对最新已优化关键帧 k：

```text
T_map_odom = T_map_imu(k) * inverse(T_odom_imu(k))
```

此变换用于当前全局输出。历史地图分别使用每个关键帧的优化位姿重建。禁止使用单个全局变换代替整条历史轨迹的修正。

GlobalBackend 发布包含版本、关键帧 ID 和位姿的结果，由系统应用到 MapStore。地图重建、相机位姿和深度导出读取同一版本。

前端局部地图、历史几何子地图与重建地图有独立生命周期。局部地图淘汰前完成所需观测保存，视觉引用和几何引用必须同步清理。

## 7. 并发与关闭

第一轮保持前端单一处理线程，按需新增写盘线程；P3 再增加后端工作线程。

| 执行单元 | 输入 | 输出 |
|---|---|---|
| 输入适配 | 传感器消息 | 内部传感器缓冲 |
| 前端处理 | 同步事件 | 不变结果与观测 |
| 写盘 | 保存任务 | 文件、索引和完成状态 |
| 后端（P3） | 关键帧任务 | 优化结果 |

所有异步队列有容量上限与积压统计。关键数据不可静默丢弃；可选重建图像可按策略拒收并计数。关键写入失败使会话进入明确的不完整状态，通知应用决定停止记录或停止运行。

关闭顺序：停止接收输入 → 完成或显式取消待处理前端任务 → 停止生产后端任务 → 完成/取消后端工作 → 排空写盘 → 写会话完成标记 → 释放模块。禁止依赖析构函数隐式吞掉写盘错误。

## 8. 目录与构建

```text
include/livo_atlas/{core,frontend,mapping,backend,io,system}/
src/{core,frontend,mapping,backend,io,system,ros}/
tools/
docs/
config/
launch/
```

仅创建有实际实现的目录。头文件迁移与逻辑变更分开提交。采用 `livo_atlas` 命名空间，按目标设置 include、链接依赖与编译选项。

拟定库边界：`livo_atlas_frontend`、`livo_atlas_mapping`、`livo_atlas_io`、`livo_atlas_system`；P3 引入 `livo_atlas_backend`。基础类型较少时不必单独建立动态库。

初期保留 launch 使用的可执行文件名与参数兼容层，迁移完成后统一处理命名，避免结构调整同时引入部署变更。

## 9. 重构完成的判断

P1 完成时：主程序只承担组装与运行；融合状态有唯一所有者；发布和文件保存不在算法函数中；模块结果具备时间和坐标语义；已有模式能够运行且结果与基线比较有记录。

验证优先覆盖时间切分、坐标变换、数据所有权、更新顺序和关闭流程。数据集尚未准备时，只能报告构建及接口检查完成，不能宣称估计行为保持一致。
