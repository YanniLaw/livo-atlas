# 空洞种子预留比例与固定预算试验

`config/gaussian.yaml` 新增：

```yaml
gaussian:
  worker:
    seed_policy: uniform
    coverage_uncovered_ratio: 0.5
```

默认策略仍为 uniform。比例仅影响 coverage，取值为有限数值 [0,1]；bool、字符串、NaN/Inf 会被拒绝。
这是每观测种子定额中**优先预留**给未覆盖有效深度像素的最大比例，
不是最终高斯中未覆盖像素的精确占比。其余定额仍在未选候选中均匀补齐，避免重复。
预留数为 `min(floor(seed_limit * ratio), uncovered_count)`；候选未超过定额、全部未覆盖或
没有历史模型时，沿用原始 uniform 初始化。比例为 0 时跳过覆盖预渲染，初始化数组与 uniform 一致。
GPU 浮点归约仍可能导致独立训练的参数不能逐位复现。

## 运行与比较

沿用[固定预算工具](controlled-gaussian-sampling.md)，复制同一份 YAML 为 0、0.25、0.5 三份配置，
只修改 `gaussian.worker.coverage_uncovered_ratio`。三组都使用 `--seed-policy coverage`，
以 coverage/0 作为等价 uniform 的基线，每组分别运行随机种子 0 和 1。
窗口保持 10、每观测至多 1000 个高斯、每观测训练 20 步，其余优化器、位姿、空间选块和观测顺序固定。

```bash
python tools/3dgs_probe/evaluate_gaussian_sampling.py \
  --map-directory /data/reference/gaussian --keyframes /data/reference/slam/keyframes \
  --prepare-executable /sdk/bin/livo_atlas_prepare_3dgs_views \
  --selector-executable /sdk/bin/livo_atlas_select_gaussian_neighbor \
  --config /data/ratio-25.yaml --seed-policy coverage --random-seed 0 \
  --output /data/ratio-25-0

python tools/3dgs_probe/compare_gaussian_sampling.py \
  --baseline /data/ratio-0-0 --candidate /data/ratio-25-0 \
  --allow-coverage-ratio-change --output /data/comparison-25-0
```

对照模式显式放行比例这一个变量。每份输出归档 `config.yaml`，原始字节摘要和实际 WorkerOptions
必须匹配；比较器仅移除比例键后核对其余 YAML 与优化器设置。学习率、深度权重、
其他 YAML 或归档文件被修改时仍拒绝比较。默认不加此开关时，仍要求配置完全相同。
新输出会验证配置归档直到发布阶段；旧的 50% 记录继续按历史默认比例校验。

## 试验口径

使用已有完整 172 帧快照：150 train、22 heldout、21 个预选查询，其中 19 个联合查询。
三组各两次，GPU 顺序执行；每次 150 次训练、3000 步，合计 120000 个最终高斯。
先核对每次预留数、预渲染次数与完整损失观测 ID，再比较单块/联合画质、覆盖新增与丢失、
六次共同覆盖的同一 LiDAR 像素上的深度 L1/RMSE，以及训练耗时和分配器显存。
PSNR 从聚合 MSE 推导，SSIM 按有效窗口加权，不能平均每个视角的 dB 代替总体指标。

现有 bag 已作为开发验证集。中间比例的敏感性结果用于判断取舍，不直接决定默认策略，
也不能用作跨场景独立测试结论。留出只针对高斯训练，SLAM 前端仍使用完整传感器流。

## 本机结果（2026-11-26）

六次均完成 150 次训练、3000 步、21 个查询，其中 19 个联合查询，最终 120000 个高斯。
配置归档、完整训练调度、全部参考/渲染产物、原始资产摘要、最终位姿和空间选块均通过核验，
只有预留比例不同。每次 0% 都无覆盖预渲染；25% / 50% 各有 137 次预渲染。
25% 两次优先预留均为 34250 个种子，50% 为 68440 / 68429；实际数量受可用空洞数限制。

## 覆盖变化与图像观察

四组比较最差六个查询均为 1、137、9、169、73、97。已查看 137 在 25% 与50%下的统一量程图：
两种比例都扩大了立面的有效支持区域，但仍有点状覆盖和明显空洞，尚未恢复完整纹理。

25% 两次联合新增覆盖为315537 /316835，同时丢失156149 /163120个原覆盖像素；
50% 新增373925 /373488，丢失113914 /113569。
降低比例并不保证更少丢失旧覆盖：当前实现会在排除预留点后重新均匀采样剩余集合，
预留比例变化会改变补齐位置。该解释是代码结构与观测相符的假设，尚未证明是唯一原因。
25% 的联合 RGB MSE 改善查询数为18/19、19/19；SSIM改善为12/19、11/19。
这些是开发验证结果，不能据此宣称不存在接缝或已经达到稠密重建精度。

## 资源、回归与复现证据

正式六次使用原有 4096 MiB 最小空闲显存、40% 分配器预算，OMP/BLAS 为1，GPU任务顺序运行。
在用户释放 Ollama 显存后才启动完整回归与正式试验。两个微型 CUDA 单测另用显式1024 MiB/20%
预算验证零比例和四分之一比例，不改变生产默认，也不计入正式试验。
GPU为 RTX4060 Laptop；各次训练分配器 peak allocated 约96.5 MiB、reserved112 MiB。
它们是训练阶段 PyTorch 分配器统计，不是整个进程或桌面服务的总显存。
训练时间0%两次差异较大；25%/50%均约23.8..24.1s。时间仅作本机描述，不作为精确开销或在线P95。
正式 GPU 试验期间有少量 CPU 校验和脚本整理，未与其他 GPU 回归任务并行。

普通预算 Python/CUDA 全套354项通过，无跳过。首轮环境显存门槛失败，以及配置归档入口的
局部名称遮蔽，均保留了日志；名称遮蔽已由现有预检测试复现并修复，再通过全套回归后才开始试验。
配置边界、准确种子序列、零比例无预渲染、真实CUDA初始化位置、配置篡改及其他优化器变化拒绝均已覆盖。

工作区 `validation/gaussian-coverage-ratio-20261126/` 包含六套原始报告/浮点样本/完整配置、
四套 `comparison-*` 报告与误差图、`audit.json` 的六次共同像素与逐查询核验、`summary.txt`。
`run_sweep.py`、`audit_sweep.py`、`summarize_sweep.py`、`test_suite.sh`、`execution.jsonl` 和
`implementation.json` 记录本机复现命令、配置及代码摘要。六套评分约2.4GiB，未复制bag或另一套模型。

## 结论与后续

保留默认 uniform 和 coverage 的历史默认比例0.5。对本场景的联合图像/深度折中，可以显式试用25%；
优先覆盖/PSNR时50%仍更强，单块SSIM优先时0%仍更好。需要其他场景复验后才能改变默认选择。

下一项值得单独验证的优化是**保留原 uniform 种子位置，再替换一部分冗余位置补洞**，
减少当前“预留后重新采样补齐集合”的位置扰动。保持容量、训练步数和窗口相同，先验证
能否减少旧覆盖丢失并恢复单块SSIM，再考虑增密或修改保留窗口。本轮不实现该算法变化。
