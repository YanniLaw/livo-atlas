# P6-02b 验证记录

状态：**P6-02b 阶段验收完成**。本文记录可选位姿图、版本化刚体尾帧和几何交付的
实际检查与尚未覆盖的范围。

## 环境与依赖

验收基线为官方 GTSAM 4.2.2 标签，对应提交
`35dd70360fb39c81081b8f420a4d72e0b896a96e`；下载归档 SHA256 为
`d4420b7ee16fc51cd9afc1f5171d6a315383fc5b58a6375466e7585d90d36d80`。
依赖安装在本阶段独立前缀，没有修改系统目录或 `vikit`。Noetic 使用 GCC 9.4、系统
Eigen 3.3.7 和 Boost 1.71；GTSAM 与工程均使用 C++17，关闭 `-march=native`，禁用
GTSAM 的 TBB 和 Metis 嵌套消元。Humble 使用 Ubuntu 22.04、GCC 11.4、系统 Eigen 3.4.0
和 Boost 1.74，采用相同的 C++ 标准和选项。两端 GCC 均使用 `_GLIBCXX_USE_CXX11_ABI=1`；
各自的 GTSAM 均在对应环境单独构建，不能跨系统复用二进制。Noetic 私有 GTSAM 动态库的
SHA256 为 `2d56ad10c5f10d828952c74b50a0d8e9a43423e153b1ee2efb8b16ebd5604f28`，
Humble 的为 `28b1fd36526b3a1612355eec3ff1af1694badc66db159a689fe653b13a07072f`。

双 ROS 验收固定使用源码提交 `77eebbe`，源码归档 SHA256 为
`d9cea56a1e5564700cc13743687df1d90f9d482d3d0b10cc592a8b0cfa9f1ce3`；
此后提交只更新验收文档。输入 `Retail_Street.bag` 的 SHA256 为
`1745bee1d570749679bad7a0392100477ab62d50aa77f7f629bc57f2a72e4427`。
测试与回放顺序执行，构建限制为单任务，回放固定单 CPU、`OMP_THREAD_LIMIT=1`，
外层启动命令使用 `nice -n 10`，且不启动 RViz。实测 Noetic 节点 nice 值为 10；
Humble 回放工具额外对节点执行 `nice -n 10`，因此实际节点 nice 值为 19，延续同环境基线的启动方式。
需要在另一台机器复现时重新构建依赖和源码；具体构建、
bag 转换与回放入口分别见[位姿图说明](pose-graph.md)、[双 ROS 说明](ros-builds.md)
和 [ROS1 验证流程](validation.md)。不同 CPU 与依赖版本不保证逐字节相同。

GTSAM 4.2.2 默认 LM 停止参数使用相对和绝对误差容差 `1e-5`、目标误差阈值 `0`，
默认 COLAMD 排序；位姿图只显式修改最大迭代次数。默认噪声是实验权重，见
[使用说明](pose-graph.md)。

## 验证结果

- 独立单元与系统场景覆盖非交换旋转、回环方向、旋转／平移噪声顺序、输入失败不污染图、
  非有限目标、迭代上限、延迟提交和陈旧版本拒绝，以及几何重建、原始位姿和前端状态保持。
  换为 C++17 依赖后，图测试和系统集成测试均通过。
- 普通共享库使用最终源码验证：启用位姿图为 37/37 个 CTest 目标通过，关闭为 35/35；两种安装
  消费者均通过。关闭模式的消费者没有加载 GTSAM；启用安装包在禁止查找 GTSAM 时明确报错。
- 普通静态库使用整理后的源码验证：启用位姿图 37/37、关闭 35/35，两个安装消费者均通过；
  启用消费者实际链接到本阶段私有 GTSAM，关闭消费者没有加载它。
- 关闭工程 OpenMP 后，启用位姿图 37/37、关闭 35/35，两个安装消费者均通过；LIO/VIO
  编译选项中没有 OpenMP 标志。
- Noetic 关闭后端时，catkin 汇总为 660 项、零失败；逐份 XML 根节点合计为 330 个用例。
  安装消费者通过，实际 ROS 节点测试
  为 10/10；完整 bag 回放无输入丢失，1351 次 LIO、1350 次 VIO，前端四组数组及发布
  内容与 P6-02a 一致，517 个原始资产和 186 个在线索引文件逐项一致。3 秒回放的 57 个
  既有导出文件也一致。这两次回放将节点固定在单个 CPU，但没有设置 `OMP_THREAD_LIMIT`，
  因此不能把它们说成与先前验证具有完全相同的线程配置。节点可执行文件的 `ldd` 解析结果
  指向本次构建且没有 GTSAM；该检查不是对运行中进程映射的直接采样。补充的 OpenMP 线程
  上限为 1 的 3 秒和完整回放也一致，并直接记录了运行中库映射；进一步的短回放确认
  实际节点的线程上限为 1、CPU 亲和性为 `[0]`、nice 值为 10。
- Noetic 启用后端时，catkin 汇总为 678 项、零失败；逐份 XML 根节点合计为 339 个用例。
  安装消费者实际链接私有 GTSAM 并通过。
  在消费该安装包时禁用 GTSAM 查找会明确报错。
  3 秒回放与 P6-02a 的前端数据、发布内容、关键帧、在线索引及 57 个旧导出文件一致；
  未限制 OpenMP 的完整回放也一致，ROS 节点测试为 10/10。另一次限制 OpenMP 为 1 的
  3 秒及完整回放也一致，并记录了运行中实际加载的节点和 15 个工程库，摘要与本次构建一致。
- 两种模式的单线程完整回放各有 1351 次 LIO、1350 次 VIO，输入无丢失，前端数组、发布

- Noetic 静态开启／关闭模式的 catkin 汇总分别为 678／660，逐份 XML 根节点合计分别为

- 使用本次 Noetic 回放的真实关键帧，在独立副本上加入**合成约束**：172 个节点、173 个

- 将上述在线版本在另一份数据集副本中显式物化后，COLMAP 的原始／优化版本各导出
  172 张图像和 17,200 个 LiDAR 初始化点；图像和相机内参一致，导出的相机平移随合成
  修正而变化，原始帧和数据集元信息保持不变。这验证的是导出链路，不是 3DGS 训练效果。
- 原位姿 schema 1 仍使用旧公式；schema 2 使用投影后的刚体尾帧公式。旧读者对新的 schema 2

  逐字节相同；对近似旋转和已有尾帧的旧／新行为均有测试。
- 10,000 帧、其中 5,000 帧为优化前缀的本机微基准，10 次物化平均耗时为旧策略约
  0.660 ms、新策略约 0.913 ms。输入是单位旋转，不是完整节点或长距离数据性能。

## 限制

本阶段没有实际回环检测，任何合成约束都不能用来评估真实闭环精度；普通 ROS 节点不会自动
启用优化。批量图、关键帧和快照内存随规模增长，尚不能推断长距离实时性。仅有约 135 秒的
`Retail_Street.bag` 时，重复回放不能替代更长的真实连续数据。优化误差下降也不证明地图正确。
没有专门向 GTSAM 内部注入求解器异常；现有失败测试覆盖非法输入和非有限初始目标，
`Optimize` 使用常量图接口并在局部构造求解状态，失败不会通过该接口改写保存的输入图。
