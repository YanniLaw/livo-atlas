# P6-03c1 在线 Gaussian 验证记录

本记录覆盖一个活动子地图的在线 Gaussian 预览，不评价重建质量，也不把该阶段称作完整
3DGS SLAM。使用方式和预算见[在线使用说明](online-gaussian.md)。

## 构建、协议和故障路径

- 独立核心 62 个 CTest 目标全部通过，XML 共记录 556 个用例，其中 2 个真实 GPU 集成
  用例在常规 CPU 测试中跳过并单独执行；全部普通公开头文件完成独立编译。3DGS 相关
  Python/GPU 回归 45 项、回放参数和比较工具回归 28 项通过。
- 普通 SDK 的 Gaussian OFF/ON 安装均通过独立消费；OFF 不导出 Gaussian 目标，ON 的独立
  消费者实际链接构造和析构函数。两个测试库的动态依赖中未发现 ROS、Python、CUDA、
  PyTorch 或 vikit。ROS1 的 catkin 消费者也验证了可选库导出。
- Noetic 通过 10 项节点参数测试，最终核心通过 20 项桥接/配置测试；Humble 的最终源码
  通过 12 项节点参数测试和 20 项桥接/配置测试。两端分别启动真实共用入口与假 socket
  worker，在没有 `/clock`
  发布者时完成初始重置，并输出回环、轨迹、几何和 Gaussian 四类关闭统计。真实 GPU
  测试在 Noetic 单独执行，而不是将 Humble 的跳过项计为 GPU 通过。
- 双端关闭构建在运行时要求 Gaussian 时，均在创建数据集和预览目录之前明确失败；关闭
  构建的节点不链接 Gaussian 桥接、CUDA、PyTorch 或 vikit。本机 Noetic 的
  `/opt/ros/noetic/lib/librospack.so` 原本就间接依赖系统 `libpython3.8`，旧版本的动态
  依赖记录也包含它；不能把 Noetic 节点称作完全不加载 Python 动态库。
- 跨语言协议测试覆盖消息截断、超限、错误会话、重复任务和超时；worker 测试覆盖独立
  RESET、确认、丢弃后清空模型/Adam、GPU 不可用和训练异常。C++ 测试还覆盖待处理帧合并、
  确认前后位姿更新、封存和切换、慢状态写入、8 对预览保留、65 帧主子地图及后端最终位姿
  通知。实际 GPU 合成测试在两帧上执行 20 步，重置后再次确认，观察到有效深度、非零梯度
  和参数更新。补充的真实 GPU 故障测试验证达到帧数上限后，Python worker 在节点调用
  `Finish()` 前观察到连接断开并退出；对应的四种受控 socket 故障路径各重复 30 次。
- 严格比较工具还检查关闭组与开启组不同、Gaussian 启用状态、预览目录归属，以及状态和
  预览的会话、任务 ID 和图像尺寸。相同回放目录或其他运行的预览不能作为有效对照。
- 对本阶段实现做过一次独立审阅。审阅指出的失败后连接未及时释放、回放来源可能误判两项
  问题均通过先复现再修复的测试验证，并在上述最终源码回放前修复。
- 10 秒官方片段还用假 worker 同时启用回环、轨迹、几何和 Gaussian：输入计数无缺失，
  Gaussian 五个候选全部确认，首个完整预览约在播放后 1.61 秒出现。这项验证用于检查回调
  共存和调度，不作为真实 GPU 训练证据。

准备过程中保留了以下环境诊断：Humble 源码覆盖保留旧文件时间戳，构建系统复用旧对象导致
链接失败，刷新副本时间戳后重建通过；一次 Noetic 联合回放在节点启动前发现 Python ROS
消息尚未生成，补建消息目标后以新目录重跑通过。最终 Humble 冒烟测试从构建目录直接启动
时，还需将该目录加入 `LD_LIBRARY_PATH`，供 ROS2 加载生成的消息类型支持库；补齐后在新
目录重跑通过。另有意构造的无 GPU、错误会话、EOF 和超时测试均应返回对应错误，前端不因
Gaussian 故障抛出异常。

## 10 秒真实 GPU 成对回放

两次均为 98 次 LIO、97 次 VIO，输入计数无缺失，正常关闭。`trajectory.tum`、
`mat_pre.txt`、`mat_out.txt`、`imu.txt` 四组数组及图像/点云发布语义严格一致，16 个原始
关键帧文件的 SHA-256 完全一致；回环最终帧数、位姿版本和接纳计数一致。

开启组观察、提交并确认 5 帧，无失败、无合并、无过期候选；峰值 pending/in-flight 均为 1。
首个完整预览在播放开始后约 2.615 秒被观察到，5 对 PNG/JSON 可读取且均记录非零梯度、
参数更新及有效深度监督。节点确认延迟平均约 0.279 秒，最大约 0.942 秒；采样的节点峰值
RSS 从约 214.8 MiB 增至 228.9 MiB。worker 报告的 PyTorch allocated/reserved 峰值分别为
70,393,344 / 92,274,688 字节，进程峰值 RSS 为 1,078,820,864 字节。这些是该次试验的
采样值，不是跨设备上限。

## 完整 bag 成对回放

以下为修复并审阅后的 `522277b` 源码成对结果；源码快照、回放和严格比较结果分别保存在
包外验证目录的 `source-final.tar`、`final-full-off/`、`final-full-on/` 和
`final-full-comparison.json`。

关闭与开启组均正常结束，输入分别收到 27,447 条 IMU、1,355 帧 LiDAR 和 1,355 帧图像，
计数无缺失；均输出 1,352 次 LIO 和 1,351 次 VIO。相同源码文件哈希、节点二进制、输入
参数和 CPU 设置下，比较结果为：

| 检查对象 | 关闭与开启的结果 |
| --- | --- |
| `trajectory.tum` | 1,352 × 8，数值完全一致 |
| `mat_pre.txt` | 2,707 × 19，数值完全一致 |
| `mat_out.txt` | 2,703 × 20，数值完全一致 |
| `imu.txt` | 27,385 × 7，数值完全一致 |
| 图像/点云发布语义 | 完全一致 |
| 原始关键帧文件 | 517 个文件 SHA-256 完全一致 |
| 回环后端 | 均为 172 帧、2 次接纳、最终位姿版本 2 |

Gaussian 共观察到 172 个关键帧、提交并确认 174 个任务；额外任务来自位姿版本更新后的
重建。共重置 16 次，最终 generation 为 15、位姿版本为 2；无失败、无超限、无过期任务，
pending 和 in-flight 峰值均为 1。首个完整预览在播放后约 2.614 秒被观察到；最终保留的
8 对 PNG/JSON 均可读取并记录真实训练、非零梯度及有效深度监督。该次数据没有触发过期
候选，确认竞争和丢弃由受控 socket 测试覆盖。

174 个确认延迟的固定分桶分别为：不超过 0.1 秒 40 个、0.1–0.25 秒 132 个、0.25–0.5 秒
1 个、0.5–1 秒 1 个，其余桶为 0；平均约 0.119 秒，最大约 0.952 秒。`Observe`/`Poll` 的
最大采样耗时分别约 0.021 毫秒和 4.24 毫秒。关闭/开启组的节点 RSS 峰值为 817.6 / 845.3 MiB；
LIO 的 p95 为 20.62 / 22.40 毫秒，VIO 的 p95 为 10.29 / 12.49 毫秒。计时受机器和调度
影响，不构成实时性保证。

最终保留预览中的进程累计峰值为 PyTorch allocated 101,218,816 字节、reserved
117,440,512 字节、worker RSS 1,098,493,952 字节。`nvidia-smi` 对整个 GPU 的 144 次
采样显示已用显存为 559–780 MiB，其中包含其他进程和驱动开销，不能与 PyTorch allocated
直接相加。两次回放后重新核验 bag SHA-256，结果一致。

## 独立故障退化回放

最终源码分别使用新的 10 秒输出目录执行以下四次 Noetic 回放。每次节点都正常关闭，均输出 98 条
轨迹；输入计数、四组前端数组、发布语义和原始关键帧文件均与短段关闭组严格一致，
Gaussian 的 `failed` 均为 1。

| 故障注入 | 节点观察到的错误 | 说明 |
| --- | --- | --- |
| 隐藏 CUDA 设备 | `gpu_unavailable` | 真实 Python worker 未回退到 CPU |
| 拦截 `gsplat.csrc` 导入 | `extension_unavailable` | 在独立 worker 中模拟扩展缺失，未改动现有环境 |
| 处理观测时终止假 worker | `send: Broken pipe` | 测试进程仅终止自己启动的 worker |
| socket 接收连接但不响应握手 | `Socket transfer timed out` | 期间最新待处理观测合并，前端继续运行 |

上述证据分别位于 `final-fail-nogpu-check.json`、`final-fail-extension-check.json`、
`final-fail-crash-check.json` 和 `final-fail-timeout-check.json`。失败后当前会话不自动重连；用户需
启动新 worker 并指定新的输出目录。文件系统或驱动层长期阻塞不在这些测试的覆盖范围内。
