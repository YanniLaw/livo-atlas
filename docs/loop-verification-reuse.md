# 回环验证内部剖析与局部复用

本文历史时间来自带线程审计探针的回放。后续发现探针显著增加 FLANN 查询开销，
不能直接用这些时间预测日常性能；查询次数和数值对照仍有效。
见 [不加载线程探针的采样与重复对照](gicp-cpu-profile.md)。

沿用 `diagnostics.stage_timing`，增加以下内部阶段，公共 SDK 接口保持不变。

| 阶段 | 范围 |
| --- | --- |
| loop_input_prepare | PrepareGeometry 的验证和下采样，不包含初始变换猜测校验 |
| loop_gicp_forward / loop_gicp_reverse | 各方向完整 Align 调用 |
| loop_quality_forward / loop_quality_reverse | 配准结果各方向的完整质量计算 |
| loop_recheck_prepare | 复核的 PrepareGeometry，不包含后续变换坐标安全校验 |
| loop_recheck_quality_forward / loop_recheck_quality_reverse | 固定变换复核的各方向质量计算 |
| loop_metric_prepare | 质量计算中的 float 点云、变换点、搜索树及局部缓存准备 |
| loop_metric_search | 对应关系搜索、互为最近邻检查和残差样本收集 |
| loop_metric_statistics | 覆盖率、残差统计与退化判定 |

`loop_quality reverse_queries=... source_points=... target_points=...`
记录反向搜索实际次数。质量计算可能出现在配准和优化后复核中，各层计时相互包含，不能相加。
开关关闭时新增阶段不读时钟、不打印日志；公共同步入口保持原有行为。

## 本轮优化

一次完整的剖析回放中，双向 GICP 累计约 13.26 秒，48 次质量计算的近邻搜索累计
约 13.36 秒，搜索准备约 0.15 秒。两处成本相近，本轮选择最小范围的精确查询复用。

同一个目标索引 j 可能被多个源点选中。目标点、变换后的源点集和搜索树在本次调用中保持
固定，所以它的反向最近源点索引也固定。缓存该索引后，每个目标索引至多查询一次；
失败查询也会缓存。缓存退出本次质量计算即释放，不跨任务或变换共享。

前向搜索、float 搜索坐标、互为最近邻判定、半径过滤、残差与 Hessian 累加顺序均保持。
新增空间为 O(目标体素数) 个 int，按公共上限 100000 体素约 400 KB。
解析用例使用 300 个原始点和 300 个偏移影子点，保持 300 个精确对应，反向搜索由
600 次降至 300 次。已有重复点并列距离用例和新增空输入用例继续检查原有语义。

## 验证范围

对比同机 CPU 集合、前端预算 2、后台线程 4、驻留预算 3 的完整 Retail_Street 回放。
结果需保持原始帧、轨迹、成员修订、候选诊断和接纳结果，再比较查询次数、耗时和内存。
单次配对只记录本机样本，不将两个并行方向的耗时之和解释成端到端加速比。

证据在 `validation/loop-verification-reuse-20261124/`。长期测试可进一步补全全部
metric/recheck 阶段及查询计数日志的开关断言；当前开关用例覆盖注册阶段，完整回放覆盖
开启后的全部阶段，独立源码复核检查了关闭路径。

## 配对结果

SDK 76 个 CTest 目标、Noetic 5 个相关目标、Humble 7 个相关目标通过。
优化前后的完整 bag 均输出 1352 次 LIO、1351 次 VIO、172 个关键帧，完成 13 次查询，
尝试 20 个候选，接纳 2 次回环，最终版本为 2。原始资产、轨迹、成员修订和语义输出字节一致，
去除耗时后的候选诊断逐值一致，归档检查均 consistent。最终位姿与旧基线差低于 1e-12。

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 质量计算次数 | 48 | 48 |
| 源点累计数 | 637,565 | 637,565 |
| 反向最近邻实际查询 | 637,565 | 273,912 |
| 近邻搜索累计时间 | 13.362 s | 11.180 s |
| 质量准备累计时间 | 0.150 s | 0.169 s |
| 验证批次累计墙钟时间 | 15.231 s | 15.028 s |
| 查询计算累计墙钟时间 | 19.546 s | 18.358 s |

实际反向查询减少约 57.0%，本次搜索累计时间降低约 16.3%。同时双向 GICP 累计时间
从 13.263 s 波动到 15.751 s，说明配对仍受运行环境影响；不据此承诺稳定的端到端加速。
峰值 RSS 分别为 868.9 和 874.1 MiB，
该指标包含整个前端与后台，不能当作局部缓存的内存成本。

本轮确认了精确计算复用的效果。下一步可继续细分 GICP 的协方差估计、迭代优化与变换校验，
确认重复成本后再决定是否复用协方差。继续保持质量阈值、float 搜索坐标和原有对应关系。
